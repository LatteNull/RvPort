## 1. 简介

### 1.1 工具定位

把 x86 / ARM 工程迁移到 RISC-V。工具做三件事：

1. **扫描**：识别源码、makefile、依赖包中所有架构相关迁移点
2. **建议**：基于规则库给出每个迁移点的修改建议
3. **AI 增强**：对单点或整文件，调用大模型给出更智能的改写建议（甚至直接改码）

### 1.2 适用场景

| 场景 | 推荐方式 |
| --- | --- |
| 单文件 / 单函数迁移 | 建议模式 AI 增强 |
| 逐文件批量化改写 | Agent 模式（按当前文件）+ patch 导出 |
| 依赖库评估 | 依赖库扫描（Python / Go） |

### 1.3 能力一览

工具按语言扫描架构相关迁移点，并给出修改建议：

| 语言 | 扫描的迁移点 |
| --- | --- |
| **C / C++** | makefile 规则、intrinsic、builtin、架构相关宏、内联汇编 |
| **Java** | JNI（native 方法）、架构相关依赖 |
| **Python** | C 扩展、ctypes / cffi 调用、架构相关依赖包 |
| **Go** | cgo（调用 C 库）、unsafe / syscall、架构相关依赖包 |
| **Rust** | 内联汇编、架构相关 crate |

通用能力：

| 能力 | 说明 |
| --- | --- |
| Web 扫描与展示 | 上传源代码 → 扫描 → 给出修改建议 |
| 文件树管理 | 新建文件 / 目录，删除文件 |
| 结果导出 | 问题表格 + patch |

> AI 增强（建议模式 / Agent 改码）的详细用法见 [§8](#8-ai-增强与代码生成)。

## 2. 登录与账号

工具为**本地部署**，访问地址由部署人员提供。用浏览器打开后进入登录页。

### 2.1 首次登录与改密

1. 浏览器打开部署地址，进入登录页
2. 输入管理员（部署人员）预先分配的**个人账号**与初始密码
3. 系统自动跳转到「修改密码」页，**强制**修改初始密码
4. 输入新密码 → 点击「**确认**」
5. 用新密码重新登录，进入主界面

点击右上角**用户名** → 「登出」，回到登录页。

## 4. 任务管理

任务管理集中在左侧任务列表：**新建、删除、查找**。任务一旦提交即开始扫描，工具**不提供**取消扫描、重新扫描、任务状态徽标、重命名、复制等操作——如需重扫，删除任务后重建。

### 4.1 新建任务

点任务列表顶部的「**➕ 添加**」按钮，进入「新建任务」页面：

- **任务名称**（必填）
- **上传文件夹 / 压缩包**：可选「选择文件夹」或「选择压缩包」（zip / tar.gz / tar.bz2 / tar.xz 等），可添加多项
  - 单次总量上限 **2 GB**，超限会提示
  - 自动跳过 `.git` / `.github` 目录
  - 提交前可点「✖」移除已选目录
- **是否扫描依赖库**：默认「否」；选「是」后选择 python 或 go 并填写配置（详见 [§5](#5-依赖库扫描配置)）

填完点「**提交任务**」。上传时显示进度，完成后自动进入任务详情页（[§6](#6-查看扫描结果)）。

![图 4-1：新建任务对话框](assets/markdown/screenshots/新建任务.png)

*图 4-1：新建任务页面*

> 上传过程不提供「取消」按钮，请确认选择后再提交。

### 4.2 删除任务

任务列表中，鼠标移到任务节点 → 点右侧「**🗑**」→ 确认弹窗（「确定删除 xxx 任务吗？任务删除后将不能恢复」）→「删除」。

删除不可恢复，会一并删除该任务的扫描结果。

### 4.3 查找任务

任务列表顶部搜索框，按任务名实时过滤。

## 5. 依赖库扫描配置

### 5.1 何时需要

仅当工程为 **Python / Go**，且需要检查依赖包中是否有架构相关问题时启用。C/C++、Java、Rust 工程**无需**配置。

依赖库扫描在「新建任务」时配置：勾选「**是否扫描依赖库 → 是**」，再选择 python 或 go（详见 [§4.1](#41-新建任务)）。

### 5.2 配置字段

| 语言 | 字段 | 是否必填 | 示例 |
| --- | --- | --- | --- |
| Python | python 解释器地址 | 必填 | `/usr/bin/python3` |
| Python | python 镜像源地址 | 可选 | `https://mirrors.aliyun.com/pypi/simple/` |
| Go | Go 安装路径 | 必填 | `/usr/local/go` |
| Go | Go 环境变量设置 | 可选 | `GOPROXY=… \| GOPRIVATE=… \| GOSUMDB=… \| GOINSECURE=…` 等 |

![图 5-1：新建依赖库扫描配置](assets/markdown/screenshots/新建依赖库扫描.png)

*图 5-1：新建依赖库扫描配置*

### 5.3 依赖库扫描的网络要求

依赖库扫描访问外部源（PyPI / Go 模块）时，通过**任务级**配置保证连通：

- **Python**：填写「python 镜像源地址」（如内网镜像源），不填则走默认源
- **Go**：填写 `GOPROXY` 等环境变量（如 `GOPROXY=https://goproxy.cn,direct`）

> ⚠️ [§11.4 网络代理配置](#114-网络代理配置) 仅用于 **AI 生成所用的 Docker**，**不**用于依赖库扫描。若依赖下载超时，请检查任务中的镜像源地址 / Go 环境变量是否可达。

## 7. 迁移建议管理（增 / 删 / 选）

每个迁移点在代码视图**顶部**维护一个**建议列表**（规则自动给出 + 你手动添加）。你可以**选中代码新增**、**删除**建议，并**选择一条**作为本次 AI 生成的方向——**建议模式必选**，**Agent 模式可选**（不选则对当前文件全部建议批量生成，详见 [§7.4](#74-选择建议)）。

### 7.1 建议列表

在代码视图（[§6.5](#65-单条问题的操作)）**顶部**查看建议列表区

![图 7-1：建议列表区](assets/markdown/screenshots/建议列表.png)

*图 7-1：建议列表区*

> Agent 模式会作用于当前文件建议列表里的**全部建议**（见 [§8.4](#84-agent-模式)）。

> 💡 切换到其他文件再切回时，AI 面板会自动收起；点代码视图**顶部**的「**显示 AI 面板**」按钮可重新展开，并**恢复上一次**的建议列表与生成结果，无需重新操作。

### 7.2 新增建议

在代码视图中**选中一段代码**（你期望的改写片段）→ 点「**将选中代码添加到AI生成建议中**」→ 该片段作为一条新建议加入列表。

![图 7-2：新增建议](assets/markdown/screenshots/新增建议.png)

*图 7-2：新增建议*

### 7.3 删除建议

在建议列表中找到要删除的条目，点其最右侧的「✖」删除。删除仅作用于**当前文件**，不影响规则本身。

### 7.4 选择建议

建议列表下拉框中「选哪一条」的行为，两种 AI 模式不同：

| 模式 | 是否必选 | 选中一条建议 | 不选（或选「全部建议」项） |
| --- | --- | --- | --- |
| **建议模式** | ✅ **必须选一条** | 以该条为方向，对单点给出改写 | **拒绝生成**，弹出提示「建议模式请选择一条建议进行 AI 生成」 |
| **Agent 模式** | ❌ 可选 | **仅针对这一条建议**所在的迁移点改写，其余迁移点不动 | 对当前文件建议列表的**全部建议**逐条应用，直接改源文件 |

> Agent 模式下，下拉框里会多出一项「选择全部建议进行AI生成（默认）」；选回这一项等价于"不选具体建议"，即回到全文件批处理。

> 简单记：**建议模式强制选一条作为方向**；**Agent 模式不选 = 全文件批处理，选一条 = 单点精修**（仍走 Agent 流水线，会改源文件）。

### 7.5 与 AI 生成的关系

- **建议模式**：以你选的**主建议**为方向，对单点给出改写（不改源文件）
- **Agent 模式**：默认对**当前文件**建议列表的**全部建议**逐条应用、直接改源文件；若选了某一条，则收敛为只针对该条改写（**可能改到其他文件**）
- 因此建议列表越准，AI 输出越准：删掉离谱的规则建议避免被误导，选对主建议让建议模式沿期望方向收敛

## 8. AI 增强与代码生成

### 8.1 两种模式

| 模式 | 是否必须选建议 | 选中一条建议时 | 不选建议时 | 是否改源文件 |
| --- | --- | --- | --- | --- |
| **建议模式** | ✅ **必须选一条** | 以该条为方向，对单点给出改写 | **拒绝生成**并提示「建议模式请选择一条建议进行 AI 生成」 | ❌ 仅给建议 |
| **Agent 模式** | ❌ 可选 | **仅针对该条建议**改写 | 对当前文件建议列表**全部建议**逐条改写 | ✅ **直接改源文件**（**可能改到其他文件**） |

> ⚠️ Agent 模式**会修改源文件**（参考范围为当前文件建议，但**可能改到其他文件**）；结果不满意可点代码视图的「**回退**」按钮恢复到应用前内容，使用前仍建议用 git 备份。

### 8.2 前置条件

两种模式都要求已配置可用的 API Key：管理员可在「**API key管理**」配置**全局共享**服务，普通用户也可配置**个人** API Key（详见 [§11.3](#113-ai-服务配置)）。若「AI 生成」不可用，检查个人与管理员的 AI 配置，并通过「测试 API Key」确认连通。

### 8.3 建议模式

**目标**：对单点迁移，以**主建议**为方向，让 AI 给出改写建议（不修改源文件）。

1. 在代码视图点目标迁移点
2. **必选**：在建议列表下拉框中选一条作为**主建议**（[§7.4](#74-选择建议)）
   - 未选时点「AI 生成」会弹出提示「建议模式请选择一条建议进行 AI 生成」，**不会发起请求**
3. 切到「**建议模式**」→ 点「**AI 生成**」
4. AI 在右侧**流式输出**改写建议，支持**复制**、**点赞 · 点踩**反馈

> 建议模式**不修改源文件**，输出仅供参考。

![图 8-1：建议模式 AI 生成](assets/markdown/screenshots/建议模式.png)

*图 8-1：建议模式——右侧流式输出改写建议，支持复制 / 点赞 / 点踩*

### 8.4 Agent 模式

**目标**：让 AI 自动修改源文件。改码粒度由"是否选建议"决定：

| 操作 | Agent 行为 |
| --- | --- |
| **不选任何建议** / 选「选择全部建议进行AI生成（默认）」项 | 对当前文件建议列表里的**全部建议**逐条应用、直接改源文件 |
| **选中某一条建议** | **仅针对这一条建议**所在的迁移点改写，其余迁移点不动 |

操作步骤：

1. 进入某文件的代码视图
2. 确认建议列表内容（删掉不想要的，[§7](#7-迁移建议管理增--删--选)）
3. 决定改码粒度：
   - **全文件批处理**：不选任何建议（或选「选择全部建议进行AI生成（默认）」项）
   - **单点精修**：在建议列表中选一条作为目标
4. 切到「**Agent 模式**」→ 点「**AI 生成**」
5. AI 逐条改写当前文件；完成后查看 diff，可下载 patch（[§10.2](#102-下载补丁patch)）

![图 8-2：Agent 模式 diff 显示](assets/markdown/screenshots/Agent生成diff显示.png)

*图 8-2：Agent 模式生成后的 diff 视图*

> Agent 模式同样在右侧**流式输出**改写过程，支持**复制**、**点赞 · 点踩**反馈（与建议模式一致）。

> Agent 模式以**当前文件的建议列表**为参考范围（不支持选「目录」或「整个任务」），但生成时**可能改到其他文件**，评审时请关注全部改动。
> ⚠️ 结果不满意可点代码视图的「**回退**」按钮恢复文件，也可用 git 回退（`git checkout -- <file>`）。

## 9. 文件管理

支持在工具内直接管理文件，无需重新上传。

### 9.1 新建文件 / 目录

**入口**：文件代码视图左侧文件树**顶部工具栏**的「**新建文件**」/「**新建目录**」按钮（不是右键菜单）。

- 点击后输入文件名（含扩展名）/ 目录名 → 确认
- 新建的空文件 / 空目录立即出现在文件树，可单击进入编辑（[9.3](#93-在线编辑)）

### 9.2 删除文件

**入口**：文件树工具栏「**删除**」按钮（先选中文件再点）。

- **不支持删除目录**，只能删除文件
- 可删除的文件：**待修改（有建议）/ 已修改 / AI 生成** 的文件
- 原始文件、缺失文件不可删（**缺失文件**只是扫描给出的提示性虚拟条目，磁盘上并不存在，因此无需也无法删除）
- 删除**不可恢复**（无撤销）

### 9.3 在线编辑

- 单击文件树中的文件 → 进入代码编辑器
- 支持语法高亮、自动缩进
- 编辑后点「**保存**」按钮写入工具内文件系统
- **保存**与 **Agent 改码**都会**自动刷新**该文件的扫描结果

| **系统日志** | 操作审计、过滤、下载 | [§11.5](#115-系统监控与系统日志) |

### 11.3 AI 服务配置

配置大模型连接，启用建议模式与 Agent 模式。

#### 11.3.1 两个配置入口

| 入口 | 路径 | 适用 |
| --- | --- | --- |
| **API key管理**页 | 右上角「设置」→ **API key管理** | 集中管理：增 / 删 / 改 / 测试 / 设默认 |
| **模型下拉框旁的按钮** | 代码视图 / 文件生成页 → 模型下拉框 → 旁边的「**管理 API Key**」按钮 | 临时跳转：在选模型时发现没有可用 Key，一键跳到 API key管理页 |

> 模型下拉框里没有可用模型时，下拉框会显示「暂无可用模型，请先配置 API Key」——点旁边的「**管理 API Key**」按钮即可去配置。

#### 11.3.2 必填字段

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| Base URL | 模型服务地址 | `https://your-llm-gateway.example.com/v1` |
| API Key | 模型服务密钥 | `sk-xxxxx...` |
| 模型名称 | 建议 / Agent 使用的模型 | `claude-sonnet-4-6` / `gpt-4o` |

填完点「**测试 API Key**」验证连通：成功即可用；失败常见原因见 [§13 Q5](#q5ai-报无法连接到-api-服务器)，如属网络问题先按 [§11.4](#114-网络代理配置) 配置代理。

#### 11.3.3 管理员 vs 普通用户

> **管理员配置**为**全局共享**，所有用户共用；**普通用户**可在此配置**个人** API Key / 模型，与管理员配置并存、可选其一使用。建议按公司密钥管理规定定期轮换。

可见性与操作权限：

| 操作 | 管理员 | 普通用户 |
| --- | --- | --- |
| 查看列表 | 全部 | 自己的 + 管理员的（**看不到**其他普通用户的） |
| 新增 / 编辑 / 删除 | 任意 | 只能操作**自己的**（不能删管理员的，也不能动其他普通用户的） |
| 设为默认 | 任意 | 只能在**可见范围**内（自己的 + 管理员的）设默认 |

#### 11.3.4 API Key 选取优先级

代码视图中选了某个模型后，系统按以下策略从候选 Key 中**自动选一条**用于本次 AI 调用。

**候选范围**：

- 管理员：全部 Key
- 普通用户：自己的 + 管理员的（不含其他普通用户的）

**选取优先级（从高到低，逐项排序后取第一条）**：

1. **模型选中项**：你在「API key管理」里对该模型**选中**的那条（每个用户对每个模型最多一条，互不影响）
2. **全局默认**：你或管理员**设为默认**的那条
3. **属于自己**：你个人配置的 Key（同优先级下，自己的优先于管理员的）
4. **创建时间**：以上均相同时，按创建顺序取靠前

> 💡 两个"默认"概念别混淆：
> - **全局默认**：决定模型下拉框**默认选中哪个模型**
> - **模型选中项**：决定**你在该模型下用哪条 Key**——优先级最高

配置后：在代码编辑器页面的模型下拉框中选择要使用的模型（个人或管理员配置的），即可用「AI 增强」（建议模式）与「Agent 模式」自动改码。

### 11.4 网络代理配置

为 **AI 生成所用的 Docker** 配置网络出口。两类用途要分清：

- **Docker HTTP / HTTPS 代理** → 访问**外网大模型**时走（如经隧道出网）
- **Docker 无需代理的主机** → 让**内网 MCP** 等地址**直连**、不走上面的代理

**内网部署且模型也在内网时通常无需配置代理**。依赖库扫描（PyPI / Go 模块）**不**走此代理，由任务级镜像源 / Go 环境变量保证连通（见 [§5](#5-依赖库扫描配置)）。

**入口**：右上角「设置」→ **网络代理配置**（管理员配置全局共享代理，普通用户可配置个人代理）

| 字段 | 用途 | 说明 |
| --- | --- | --- |
| Docker HTTP 代理 | 访问**外网大模型**的 HTTP 代理 | 内网无法直达模型时，填隧道本地端口 `http://127.0.0.1:端口号` |
| Docker HTTPS 代理 | 访问**外网大模型**的 HTTPS 代理 | 与 HTTP 代理填**同一个** `http://127.0.0.1:端口号` |
| Docker 无需代理的主机 | **内网 MCP** 等需直连、不走代理的地址 | 逗号分隔；填入后这些地址绕过代理直连 |

> 代理地址由部署环境决定，按实际填写。

> 💡 **内网无法直达大模型时的常见做法**：在服务器上搭建一条到模型服务的隧道（监听本地端口），把「Docker HTTP 代理」「Docker HTTPS 代理」**都填** `http://127.0.0.1:端口号`；同时把**内网 MCP** 等地址加入「Docker 无需代理的主机」，确保它们直连而不被代理劫持。完成后回到 [§11.3](#113-ai-服务配置) 测试 API Key 连通（详见 [Q5](#q5ai-报无法连接到-api-服务器)）。

配置后回到 [§11.3](#113-ai-服务配置) 测试 AI 连接，验证可达性。

### 11.5 系统监控与系统日志

**系统监控**：展示 **AI 使用次数**、**累计处理任务数量**等总体指标，便于容量概览（**当前版本暂未提供**）。

**系统日志**（管理员 → 设置 → **日志管理**）记录每次关键操作，字段含：操作用户、操作名称、所属工具、操作结果、操作主机 IP、操作时间、操作详情。支持按时间 / 用户 / 事件过滤，并可「**下载日志**」导出。

## 12. 端到端操作示例

**场景**：把一个使用 ARM NEON 的 C 工程（`demo-arm64`）迁移到 RISC-V RVV。

1. **准备**：用 git clone 工程到本地，commit 一次作为基线；浏览器打开部署地址，使用个人账号登录，点击「迁移工具」页签。
2. **创建任务**：「新建任务」→ 任务名 `demo-arm64-20260625` → 压缩包上传 `demo-arm64.tar.gz` → 等待自动扫描。
3. **查看结果**：问题统计摘要按类型列出（intrinsic 65 / 宏 12 / builtin 8 / 汇编 2，影响行数 412）；在「源码扫描信息」点开 `src/simd/vec_add.c` 的某条问题，进入代码视图。
4. **单点推理（精修关键函数）**：在代码视图点 `vec_add.c` 第 23 行（`vadd_u8`）的下划线建议 → 规则建议 `__riscv_vadd_vv_u8m1` → 点「AI 生成」（建议模式）让大模型给出考虑 LMUL 的改写。
5. **Agent 改写当前文件**：在 `vec_add.c` 代码视图确认建议列表 → 切「Agent 模式」→「AI 生成」对当前文件逐条应用并改源文件 → 查看 diff，关注 NEON → RVV 的语义覆盖。其余文件逐一重复。
6. **下载补丁并应用**：任务卡片点「下载」得到 `.patch` → 在本地下：

   ```bash
   cd demo-arm64
   git checkout -b riscv-migration
   git apply migration-demo-arm64-20260625.patch
   git diff    # 人工评审
   ```

7. **失败回退**（Agent 改码后某文件编译失败时）：

   ```bash
   git checkout -- src/simd/vec_add.c   # 回退单文件
   git checkout -- .                    # 全部回退
   ```

## 13. 常见问题 FAQ

### Q1：登录后页面空白 / 一直 loading？

- 清浏览器缓存与 Cookie
- 换浏览器（Chrome / Edge / Firefox 较新版本）
- 联系管理员确认服务健康

### Q2：上传代码失败 / 一直卡在上传中？

- 单次上传总量上限 **2 GB**，超限会提示，请减少文件后重试
- 网络不稳定 → 改用更稳定的内网
- 浏览器插件拦截 → 关闭广告拦截 / 代理插件
- 上传过程**无法中途取消**，请确认选择后再提交

### Q3：扫描结果显示「缺失文件」？

指 x86 / ARM 工程中存在、但 RISC-V 缺失、需要**新建**的文件（而非在已有文件里改几行代码）。处理：点「**AI 生成**」→ 选择**参考架构**（如工程里的 `aarch64` / `arm` / `x86` 目录）→ AI 参考该架构下的同名文件生成 RISC-V 版本并新建该文件。

> 缺失文件**只支持 Agent 模式**，建议模式不适用。

### Q4：依赖库扫描提示找不到 Python / Go？

- 在任务配置中填写正确的解释器路径（如 `/usr/bin/python3`）
- 联系管理员确认部署环境已安装对应版本

### Q5：AI 报「无法连接到 API 服务器」？

排查顺序（管理员或用户均可处理；普通用户可配置**个人** AI Key / 代理，见 [§11.3](#113-ai-服务配置)、[§11.4](#114-网络代理配置)）：

1. 检查 Base URL 拼写
2. 在「设置 → 网络代理配置」给 **Docker HTTP / HTTPS 代理** 填上可用的代理地址
   - **内网无法直达大模型时**：在服务器上搭建隧道（监听本地端口），把「Docker HTTP 代理」「Docker HTTPS 代理」都填 `http://127.0.0.1:端口号`
3. 在「设置 → API key管理 → 测试 API Key」验证
4. 确认模型服务可用、配额未耗尽

详见 [§11.4 网络代理配置](#114-网络代理配置) 与 [§11.3 AI 服务配置](#113-ai-服务配置)。

### Q6：点「AI 生成」没反应 / 弹出提示？

「AI 生成」按钮**不会置灰**。点击后可能弹出以下提示，按提示处理即可：

| 提示文案 | 含义 | 处理 |
| --- | --- | --- |
| 「**请选择模型**」 | 还没选模型 | 在模型下拉框选一个模型再生成 |
| 「**建议模式请选择一条建议进行 AI 生成**」 | 建议模式下没选建议 | 在建议列表下拉框中选一条作为主建议（[§7.4](#74-选择建议)） |

下拉框里没有可选模型时（下拉框显示「暂无可用模型，请先配置 API Key」），说明尚未配置 AI 服务：可点下拉框旁的「**管理 API Key**」按钮直接跳转配置，或走「设置 → API key管理」（普通用户可配置**个人** API Key，或联系管理员配置全局共享服务，详见 [§11.3](#113-ai-服务配置)）。

### Q7：Agent 模式改坏了源文件怎么办？

可在代码视图点「**回退**」按钮，把文件恢复到 Agent 应用前的内容。也可用 git 回退：Agent 启动前用 `git commit` 保存基线，出问题后 `git checkout -- <file>` 或 `git checkout -- .`。

### Q8：导出的 patch 在本地 `git apply` 失败？

- 确认 patch 与代码基线一致（任务扫描时的版本）
- 用 `git apply --3way` 尝试三方合并
- 用 `patch -p2 --merge` 处理冲突

### Q9：建议列表里的规则建议可以删吗？

可以。删除仅作用于当前任务，**不影响规则库本身**。下次扫描时，若该规则的**文件 + 行号 + 内容**与删除时一致，则不再出现；若因代码变动导致行号变化，则该规则会重新提示。

## 14. 附录

### 14.1 术语

| 术语 | 含义 |
| --- | --- |
| **intrinsic** | 编译器内建函数，对应 SIMD / 向量指令 |
| **builtin** | GCC / Clang 的 `__builtin_*` |
| **RVV** | RISC-V Vector Extension |
| **LMUL / VL** | RVV 的向量寄存器分组与长度 |
| **建议模式** | AI 仅给建议，不改源文件 |
| **Agent 模式** | AI 直接修改源文件 |
| **建议列表** | 单个迁移点的多个候选改写集合 |
| **主建议** | 建议列表中被勾选作为 AI 主输入的那一条 |
| **MCP** | 供 AI 调用知识库的协议；内网部署时通常走直连、不走代理（见 [§11.4](#114-网络代理配置)） |

### 14.2 RISC-V intrinsic 头参考

| 头文件 | 用途 |
| --- | --- |
| `riscv_vector.h` | RVV 向量指令 |
| `riscv_crypto.h` | 加密扩展 |
| `riscv_ntlh.h` | 非时间局部性提示（prefetch） |
| `riscv_bitmanip.h` | 位操作扩展 |
