# RvPort 前端 UI 方向

[English](AGENTS.en.md) | 简体中文

## 产品定位

RvPort 是面向个人用户的迁移门户，不是企业后台管理系统。Ant Design 只提供稳定的交互基础，不能决定页面的视觉气质。

## 默认视觉规则

- 优先用留白、字号、字重、颜色和内容顺序建立层级。
- 不用边框、分割线或盒子矩阵装饰页面；线条只用于真实边界、进度、流程关系、输入焦点和必要的状态反馈。
- 内容容器优先使用轻柔底色和空间分组。阴影只用于悬浮、弹层等确有层级变化的场景。
- 列表卡片应讲清一条连续故事：项目是什么、当前进行到哪里、有什么结论或阻碍、用户下一步做什么。
- 不把业务结论拆成仪表盘式指标格；优先使用自然语言摘要，并只突出真正异常的内容。
- 每个区域保持一个明确主操作。次要操作降低视觉权重，不用大量描边按钮竞争注意力。
- 主蓝只用于关键行动和进行中的状态；成功色、警告色、风险色按语义克制使用。
- 保持三档桌面宽度、键盘焦点、可读对比度和 `prefers-reduced-motion` 支持；不新增移动端专用布局。

新增或调整页面时，先检查它是否更像一个帮助用户继续完成任务的门户，而不是一张等待填写和管理的数据表。

## 代码结构规则

- 字号、字重、行高和间距遵循 [样式规范](docs/STYLE_GUIDE.zh-CN.md)。主题数值只在 `src/theme.ts` 定义；页面及区域标题使用 `src/styles/mixins.scss` 的语义 mixin，保留内部次级信息层级。

- 页面入口负责组合视图；数据请求、状态转换和复杂展示分别放入 `use*.ts`、`queryKeys.ts`/`queries.ts`、`presentation.ts(x)` 与 `components/`。
- 不从一个业务阶段目录引用另一个阶段的内部组件、工具或 CSS Module。跨阶段复用先提升到最近的公共 `components/` 或 `utils/`。
- 页面代码直接从具体 API 模块导入，避免从聚合 barrel 导入整个业务域。
- React Query 的 key 统一由领域 query-key 工厂生成；同一数据在同一视图树中只建立一个查询订阅。
- 领域类型按业务模块拆分，并由使用方直接从领域模块导入，不保留旧入口的兼容 re-export。相同业务概念只能有一个权威类型定义。
- 页面入口建议控制在 300 行左右，Hook 建议控制在 250 行左右；超过时按职责拆分，不按行数机械切割。
- 测试与实现按领域就近放置；大型契约测试按 API 模块拆分，避免形成单个全量测试文件。
