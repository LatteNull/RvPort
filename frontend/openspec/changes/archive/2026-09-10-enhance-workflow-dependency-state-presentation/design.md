## Context

Workflow 拓扑由前端固定维护，后端 Overview V2 只返回节点自身的 `PENDING`、`RUNNING`、`DONE` 和 `BLOCKED` 状态。后端 readiness 会查询当前源码、环境版本和领域记录，是执行时权威校验；本次需要的是帮助用户理解固定流程关系的展示状态。

## Goals / Non-Goals

**Goals:**

- 用一套可测试的纯前端规则表达“可开始”、“等待前置”和“上游阻塞”。
- 让节点和连线共享同一份派生结果。
- 保留后端阶段状态的事实属性和执行权威。

**Non-Goals:**

- 不判断环境是否可用、当前源码是否存在等 readiness 领域条件。
- 不自动启动或禁止 Drawer 内的操作。

## Decisions

### 前置关系作为前端展示拓扑的显式属性

每个节点在 `topology.ts` 中声明 `prerequisiteIds`。不直接把所有 React Flow edge 当作前置条件，因为 `manual -> assets` 和 `optimize -> assets` 是回流表达，参与计算会引入循环。

### 事实状态与链路阻塞状态分层

节点图标始终表达后端返回的 `RUNNING`、`DONE`、`BLOCKED` 或 `PENDING` 事实状态。链路阻塞是独立的展示属性，只传播到尚未执行的后续节点；遇到 `RUNNING` 或 `DONE` 节点时停止，不用当前上游失败追溯覆盖已经发生的事实。

`PENDING` 节点先检查阻塞，再检查未完成，最后判断可开始：

1. 任一前置节点为 `BLOCKED` 或其辅助状态为 `BLOCKED`，当前节点为 `BLOCKED`。
2. 否则，任一前置节点不是 `DONE`，当前节点为 `WAITING`。
3. 否则，当前节点为 `READY`。

先将前置节点聚合为单一 `DependencyState`，再使用 `switch` 完成枚举映射。

### 连线和汇合点是前置语义的视觉载体

- 完成的上游路径使用克制的实线。
- 运行中路径使用主蓝流动线。
- 未完成路径使用灰色虚线。
- 失败根节点及其尚未执行的后续前向节点和连线使用红色视觉链路，已完成路径保持完成色。
- feedback edge 保留现有紫色回流样式，不参与前置状态计算。

知识库扫描和依赖分析在评估报告前先进入一个展示用汇合点。汇合点以 `n/2` 显示当前未受阻塞且已完成的直接输入，并使用完成、运行、等待和阻塞颜色。任一输入链路被阻塞时，汇合点优先显示阻塞。

### 节点保留单一卡片并增加动态状态说明

节点继续使用单一卡片结构，移除固定业务副标题和竖向文字状态条。左侧图标只映射后端返回的节点自身状态；第二行只显示“已完成”、“等待源码管理”、“受知识库扫描阻塞”等动态说明，并允许自然换行为两行，避免关键信息被省略。完成和待处理节点使用干净白底，通过状态色边界、短侧边标记、图标和轻阴影建立层次；运行和错误状态可使用轻量状态底色强化关注，避免所有状态底色与分组背景叠加。

### 将处理动作与主交付路径分层

评估报告到构建验证、自动化测试和归档保持紧凑的水平主路径。人工修复对齐在评估报告正下方，优化闭环对齐在自动化测试正下方，两条支路均从源节点底部垂直引出；处理完成后通过带文案的紫色 feedback edge 返回源码管理。

### 分组框使用柔和主题区分

画布保留“基础准备”、“扫描与分析”、“评估与处理”和“验证与交付”四个分组框。每组使用不同的低饱和背景、实体边界和带色点的标题标识，在增强分区感的同时不与节点状态竞争。

### 执行上下文展示任务事实

Overview V2 的 `recentTasks` 映射到前端模型。执行上下文按 `RUNNING`、`QUEUED`、`PENDING` 顺序优先选择活动任务，没有活动任务时展示后端倒序列表的第一条最近任务。卡片展示任务类型、状态、活动任务进度和消息；标题区提供“最近任务 N”轻量入口，浮层按后端顺序展示最多五条任务的类型、状态、时间、消息及活动进度，不在前端重复排序。推荐阶段继续由 Workflow 节点承担，不在摘要中重复。

## Risks / Trade-offs

- [Risk] 前端拓扑规则与后端真实 readiness 不完全一致。 → Mitigation：辅助状态只描述画布上的节点关系，不参与执行决策；Drawer 提交仍以后端校验为准。
- [Risk] 阻塞传播会让多个后续节点同时呈现阻塞。 → Mitigation：只传播到尚未执行的节点，并在已完成或运行中节点处停止。

## Migration Plan

1. 增加前置拓扑和纯函数派生模型。
2. 让节点、连线和窄屏列表消费派生模型。
3. 补充规则单元测试与结构共享测试。
4. 执行前端质量检查和 OpenSpec strict validation。
