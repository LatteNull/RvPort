## Why

当前 Workflow 只将后端阶段自身状态映射到节点，连线也只表达静态拓扑。当节点仍为 `PENDING` 时，用户无法判断它是已可开始、正在等待上游，还是已因上游失败而被阻塞。

后端 Overview V2 已恢复最近五条任务，但前端尚未映射该字段，执行上下文仍展示与画布重复的推荐阶段。

## What Changes

- 在前端固定 Workflow 拓扑中显式定义每个节点的展示级前置节点。
- 基于 `overview.workflow.stages` 的服务端事实状态，在前端纯函数中推导 `READY`、`WAITING` 和 `BLOCKED` 辅助状态。
- 将等待、流转、完成和阻塞语义映射到连线，并在节点第二行展示动态状态说明。
- 为评估报告增加输入汇合点，以 `n/2` 直接表达知识库扫描和依赖分析的汇合情况。
- 将人工修复和优化处理收敛为主流程下方的回流支路，并标明回到源码管理的语义。
- 移除 Workflow 节点的固定业务副标题和竖向文字状态条，以状态色侧边标记、轻渐变和动态说明增强卡片层次。
- 保留四个业务分组框，以不同的柔和主题色、实体边界和标题标识增强区分。
- 当任一节点阻塞时，将阻塞传播到尚未执行的前向节点和连线；遇到已运行或已完成节点时停止，避免追溯污染事实状态。
- 窄屏列表复用同一份辅助状态推导结果。
- 映射 Overview V2 的 `recentTasks`，执行上下文优先展示活动任务，否则展示最近终态任务，并通过轻量入口查看最近五条任务。

## Capabilities

### Modified Capabilities

- `project-pipeline-workbench`: 增加前端展示级依赖状态、阻塞传播和连线语义。

## Non-Goals

- 不修改后端 Overview、Workflow 或 readiness API。
- 不在前端复制后端的数据库前置条件判断。
- 不将辅助状态用于允许、禁止或发起真实任务。
- 不修改后端执行顺序或任务依赖；汇合点、支路和阶段带只是前端展示拓扑。

## Impact

- 影响 `src/pages/project-detail/Workflow/`、项目工作台执行上下文、Overview 类型映射和相关单元测试。
- 无后端 API 或前端公共类型契约变更。
