## Why

`inline-project-stage-workspace` 已归档，当前前端复查确认 10 类会话、异步提交、导航及失败恢复问题，并发现 3 项数据订阅、布局测量和组件依赖优化。现有 519 项测试通过，但未覆盖本轮受控诊断复现的边界，需要在同一 change 中修复并补齐正确行为的验收。

## What Changes

| F2   | P1     | 隔离任务日志会话、cursor、读取锁、调度及完成回调，避免旧任务响应影响新任务、跳过日志。                    |
| F3   | P2     | 环境保存、预检和脚本提交采用完整 busy 与编辑会话保护，覆盖保存后验证提交、异步私钥导入及部分成功处理。    |

| F5   | P2     | 消除已有凭据提示与必填校验冲突，明确保留/替换模式，同步用户名初始化、领域类型及请求适配。                 |

## Capabilities

### New Capabilities

无；沿用现有能力归属。

### Modified Capabilities

- `frontend-application-foundation`：认证数据、会话校验与迟到成功/失败隔离（F1）。
- `task-log-viewer`：日志会话隔离与迟到响应保护（F2）。
- `common-ui`：业务弹窗提交保护与表格筛选单次通知（F4、F9）。
- `environment-management`：完整提交保护、凭据与用户名、历史返回和详情恢复（F3、F5、F6、F7）。
- `admin-center`：邮箱配置加载、刷新恢复与编辑草稿保护（F8）；弹窗规则引用 common-ui。
- `project-pipeline-workbench`：阶段加载与导航隔离（F10）。
- `project-overview-current-context`：统一 overview 订阅及刷新所有权（O1）。
- `frontend-performance-optimization`：表格高度测量按需启用（O2）。
- `frontend-code-reuse`：跨阶段详情展示组件公共依赖边界（O3）。

## Impact

二次诊断后的补充范围：项目描述和知识库扫描的异步校验归属、跨项目/账号的阶段状态隔离、项目级 SSE 的认证生命周期，以及自动化测试批次的部分失败恢复。随后按职责拆分依赖分析和模型配置，直接迁移领域 API、类型与调用方，删除无生产使用的旧代码；不保留兼容入口。

再次复查补齐写操作的统一会话归属（含公开认证表单、管理中心及阶段操作）、任务日志事件的旧会话隔离、创建项目和迁移输入的跨账号保护；401 以外的认证检查网络错误保留当前会话，403/网关错误提供普通反馈。需要完整候选集的选项与聚合读取执行完整分页，报告/日志/模型状态提供局部失败恢复；领域 API、类型与 query key 直接归属各模块，删除无人调用的旧入口和聚合 barrel。以上调整均在前端完成并补齐回归。

继续复核增加：迁移问题的 pending 与本地状态按提交 token 隔离，导入结果必须匹配来源记录；Git 首次同步按已有任务状态恢复失败表单；主动取消请求不显示网络错误；报告源码各省略片段独立跟踪加载；浏览器存储不可用时保持当前会话登录能力。

仅修改 `frontend/`：应用 Provider、认证 store、请求客户端的会话归属和相关登录/退出入口；日志 Hook；BaseModal 与提交消费方；环境表单、前端 API 类型/适配、历史和详情；邮箱页；BaseTable；项目页导航与 overview 消费方；公共详情组件及现有阶段调用方；对应就近测试。

不新增接口、依赖、业务任务或持久化草稿，不修改后端代码。环境更新与预检沿用已明确的现有接口契约，前端通过类型、请求适配和隔离 fixture 验证保留/替换凭据，不回显或持久化已保存的密码和私钥。本轮诊断依据前端代码与测试；安全登录态验收不擅自提交真实业务任务或修改真实凭据。

全量复核补充：构建详情刷新、管理弹窗异步校验、环境列表行操作生命周期、x86 到知识库的前置条件失效、表格跨资源数据隔离、报告输入统一刷新、模型探测首次失败恢复，以及无调用旧组件/筛选分支清理。覆盖清单与证据边界见 [full-audit.md](full-audit.md)。
