## Goals / Non-Goals

Goals：异步结果只更新所属会话；提交状态覆盖完整动作；失败可恢复；将 10 类问题与 3 项优化各自映射到可验证的任务，保持现有业务和视觉。

Non-Goals：不新增状态库或接口，不改变服务端认证/任务状态机，不增加全量草稿持久化，不做全量重构或编辑器资源优化，不修改后端代码。主规范只在交付后同步本 change 的目标行为。

## Decisions

### 1. 统一认证会话边界（F1）

在共享层处理身份改变与确认退出：取消旧私有查询、移除旧身份缓存，并用会话归属阻止迟到查询/提交结果回写新身份。进入新身份的受保护页面前完成隔离，覆盖主动退出、强制改密退出和会话失效后的重新登录；失败的退出不伪造已退出。记住账号功能只保留账号字符串，沿用当前规范。

认证 store 的 `refreshUser`、`ensureSession` 与请求客户端同样记录所属会话 generation：旧认证成功不得覆盖新用户，旧失败（包括旧请求的 401）不得清除新登录、重定向或触发新会话的失败反馈。会话校验 Promise 按 generation 去重，旧 Promise 的 finally 仅释放自己，不清除新会话的校验锁；路由 guard 不得因旧校验拒绝而退出新会话。同一有效会话仍复用在途校验及既有 TTL。

单纯 invalidate 仍会先展示旧缓存，仅在首页增加 userId key 又会遗漏其他私有数据，所以不作为完整修复。实现时选择清理范围或身份命名空间，但必须在统一入口满足同一验收契约，不在各页面复制登出清理。

### 2. 日志异步状态归属于具体会话（F2）

任务、enabled 生命周期或 effect 重启建立独立 session/generation。cursor、目标游标、draining、完成通知和重试调度均受归属保护；每次 await 后和 finally 修改状态前重新校验。旧响应、旧事件和定时器不得修改新会话或调用其完成回调。

取消请求仅是资源优化，不替代归属校验；可复用 disposedRef 会被新 effect 重置，单独给展示 state 加 taskId 也无法保护共享 cursor。保留当前串行增量、退避和终态收尾规则。

### 3. 环境提交采用完整 busy 事务（F3），弹窗共享显式保护（F4）

环境保存、连接预检和脚本执行在校验/请求开始时建立忙碌状态，完整覆盖保存后的验证提交。期间禁止修改 Form、上传私钥、编辑代码及局部退出；校验失败或保存/预检/脚本提交失败时解锁并保留输入，busy 在 finally 释放。成功只操作所属编辑会话；预检结果绑定当前配置快照，不将“预检任务已提交”当成连接已成功。

保存接口成功即认定环境已保存，后续连接验证提交是独立结果，不回滚保存。若本次配置已提交预检，继续调用已保存环境的连接验证接口，busy 覆盖到该请求结束：提交成功后关闭所属表单、刷新列表并提示“环境已保存，连接验证已提交”；提交失败仍关闭所属表单、刷新列表，仅提示“环境已保存，但连接验证未能提交，请在环境列表中重新检查”。不得把部分成功显示为保存失败、保留可重复创建的表单或自动重发保存；恢复路径复用列表现有环境检查入口。验证任务提交成功不等于连接成功，busy 不覆盖服务器任务运行期。上述关闭、刷新和反馈仍受编辑会话及认证会话归属约束。

异步私钥导入也受编辑会话和 busy 约束：开始提交或关闭/切换表单时取消可取消的 FileReader，并在 onload 回写前核对所属表单及 busy；已开始的读取不得在提交中或后来打开的表单中写入秘密或标记。

BaseModal 支持明确 busy 契约，覆盖 X、ESC、蒙层、footer 与实际输入控件；领域 busy 由消费方提供，共享组件不内置 API。异步输入上传等也应在忙碌状态下停止修改。普通非 busy 弹窗保留既有关闭规则，环境非提交状态仍走未保存确认。

本轮选择暂停环境提交期间编辑，而不是引入完整草稿版本合并。不能仅禁用 footer 取消；旧提交回调还必须校验所属会话，避免项目切换/重新挂载后覆盖新编辑。

### 4. 区分保留与替换凭据（F5）

环境编辑明确区分保留已有凭据和显式替换认证信息。保留时不要求秘密，也不发送表示新建凭据的 loginType/秘密字段；显式替换、变更认证方式或尚无凭据时执行对应用户名、密码/私钥校验。

前端更新适配沿用已明确的保留凭据契约：保留时省略 loginType 与秘密字段。必须同时修复表单校验、领域类型及更新适配；只移除 required 会继续触发后端新建凭据路径。编辑态预检按下述既有契约执行，不回显秘密、不新增接口。

依据已明确的现有响应契约，前端应保留 `credential.id` 与 `username`；当前环境适配遗漏这些字段。补齐环境领域类型与适配，保留原凭据引用及用户名，用于编辑初始化与预检，不把凭据 ID 当作密码/私钥或持久化表单草稿。

- 保留凭据：调用 `POST /projects/{projectId}/environments/test-connection`，发送当前表单的角色、架构、主机、端口、用户名、跳板机和工作目录，以及原 `credentialId`；不发送 `loginType`、密码或私钥。预检使用尚未保存的配置，不调用已保存环境接口来代替编辑态预检，也不隐式保存。
- 新建、替换凭据或变更认证方式：使用同一预检接口，发送当前配置及本次输入的 `loginType` 和对应秘密，不携带原 `credentialId`；引用旧凭据与提交新秘密必须互斥，避免替换意图被混合 payload 覆盖。
- 显示已有凭据但缺少可用 `credentialId`：保留凭据的普通更新仍可通过省略认证字段提交；编辑态预检明确禁用并说明“无法引用已有凭据，请保存后在列表中检查，或选择替换凭据”，不得自动切到已保存配置预检或索取旧秘密。服务端拒绝凭据引用时展示失败、解锁并保留输入，不自动改用其他凭据。

保留凭据的预检仍校验当前连接配置和用户名；预检提交标记绑定配置快照及所选凭据模式/引用，任何相关修改均使其失效。保存成功后的验证使用 `POST /projects/{projectId}/environments/{environmentId}/test-connection`，只验证本次已保存配置；其部分成功处理见决策 3。

### 5. 环境历史纳入共同局部作用域（F6）

将阶段列表状态作用域覆盖主 StageSurface 及其 sibling 执行 Drawer，保留组件原来的展示关系。按项目、阶段和环境数据集隔离；日志详情返回恢复页码/每页条数，关闭整个阶段清空，关闭日志详情不等于关闭阶段。不常驻隐藏历史列表，也不复制返回前的业务数据。

采用共同父级作用域而不是在 Executions 内创建 Provider，因为后者随进入日志而卸载，仍无法恢复。通用往返规则引用 project-pipeline-workbench，本 change 只补环境消费方遗漏。

### 6. 明确首次失败与已有数据刷新失败（F7、F8）

环境详情传递完整 query 状态，区分 pending、error、无记录和成功；失败展示重试与返回。邮件配置首次失败提供局部错误/重试，后台刷新失败保留旧数据和明确提示，不清除编辑输入；刷新成功也只更新查询数据和非编辑展示，不重填当前编辑草稿。进入编辑时以最新配置初始化，明确取消时恢复最新配置，保存成功时按所属提交结果重置；正常刷新不得清空本次输入的 SMTP 密码。复用请求客户端错误边界，不重复解析协议或修改全局错误路由。

不能将无 data 等同 loading，也不能以全局 toast 替代页面恢复入口。请求未完成、失败、空数据与恢复成功分别测试。

### 7. 表格 updater 保持纯函数（F9）

外部筛选 onChange 放在单次交互路径，不在状态 updater/effect 内触发。保留筛选回到第一页、清空草稿和正常防抖行为；StrictMode 与连续更新测试验证单次通知及正确最终条件。不把重复回调直接推断成当前每个筛选都重复请求。

### 8. 阶段预加载不控制导航（F10）

点击阶段时立即按既有 URL 导航，由阶段 Suspense 显示加载状态；预加载可以在用户意图出现时独立执行，但完成/失败回调不执行导航。迟到加载不得覆盖后来选择的阶段、Workflow/Step、其他项目或已离开的页面。保留路由 blocker、未保存确认、浏览器前进后退和项目 SSE 生命周期；预加载失败不产生未处理 Promise 拒绝，阶段加载错误由既有路由错误边界提供恢复入口。

### 9. overview 单一订阅所有权（O1）

项目页建立唯一 overview 查询订阅，在最近的项目公共边界通过有类型的上下文提供数据、加载/错误状态及显式刷新能力，阶段消费该边界，不重复建立 useQuery，也不复制服务端数据到本地 state。查询 key 仍由领域工厂生成；独立渲染消费方的测试使用该公共边界，不通过新增兜底查询恢复多订阅。

共享 key 已复用缓存与在途请求，因此不把当前多个观察者描述成多次网络请求。优化目标是清晰的数据与刷新所有权：保留项目 SSE 的 baseline、合并失效、局部 mutation 合并缓存和关闭阶段后的项目级更新，不新增全量刷新、固定轮询或第二套当前事实。

### 10. 表格测量按需启用（O2）

useTableViewportHeight 接收明确 enabled，BaseTable 按当前是否使用测量高度决定启用。现有 autoHeight 模式直接采用传入 scroll，不消费 viewportHeight，因此不注册测量 observer/resize listener，也不读取布局。启用模式仍保留现有高度公式、相同高度不提交更新和第三方表格边界；切换到停用或卸载时清理监听，重新启用重新测量，停用结果不得影响当前滚动策略。

### 11. 跨阶段共享详情组件公共化（O3）

将 AssessmentReport 与 KnowledgeBase/DependencyAnalysis 共同使用的 FindingDetail、DependencyResultDetailContent 及必要展示依赖提升到最近公共 components/，各阶段直接从公共模块导入。共同样式随展示职责移动，公共模块不得依赖阶段内部组件、工具或 CSS Module；阶段专属文案与动作仍由阶段提供，共享组件通过有类型的数据/回调表达职责。

只整理实际复用链路，不拆分无关页面，不新增仅转发的包装或旧路径兼容 re-export，不改变现有查询 key、详情内容、代码定位、加载/错误状态和视觉。保留原领域就近测试并同步导入；检查依赖方向并用现有详情与报告导航测试验收。

### 12. 全面收敛提交、完整数据与失败恢复

领域写操作统一通过会话归属包装执行：在提交入口同步锁定身份、业务对象及可见生命周期，在首个请求前、每次 await 后和回调写缓存/提示前校验归属。公开认证表单同样防止重复提交和迟到结果；任务日志 EventSource 的旧事件在关闭后不得继续写入新会话。登录校验只有明确的 401 才退出当前身份，网络失败保留会话并交给可恢复的错误边界；普通 403 与网关错误不强制导航。

创建项目、迁移输入、自动化测试、自动修复、报告及管理中心写入沿用统一规则，提交期间冻结相应表单、选择与关闭入口。部分成功不得伪装为全部失败；源关联状态按当前记录定位。需要完整候选集的选项和聚合读取使用受认证 generation 与 AbortSignal 约束的分页读取，可见列表仍使用服务端分页。报告文件、任务日志和模型绑定的读取失败在原位置提供明确状态与重试。

管理中心用户、邮件、Worker API/类型及本轮涉及的 query key 移入对应领域；调用方直接导入。没有生产调用的旧接口及项目/管理中心聚合 barrel 删除，不提供兼容转发。仅对实际会话、分页与恢复边界添加回归，保留既有 Workflow/Step 和视觉。

迁移问题的本地确认状态绑定提交 token，pending 从所属提交直接派生，避免旧 onSettled 被正确隔离后留下永久 loading。导入返回只接受匹配 sourceRefId 的条目，匹配失败走现有分页查询，不猜测第一条记录。Git 源码导入以 overview 的近期任务为准，提交返回仅作服务端数据到达前的临时状态；一旦服务器观测到该任务即删除本地快照。失败、取消或超时恢复表单并保留仓库/Ref，敏感 Token 在提交被接受后清除。

请求取消保留 Axios 取消语义并跳过网络错误 toast。报告源码按 gap 标识分别持有同步在途集合和展示 loading，允许不同片段并行，同一片段去重。认证与记住账号的浏览器存储读写采用可失败缓存，存储受限时保留内存状态，认证结果与导航不依赖缓存成功；不扩大持久化范围。

## Risks / Trade-offs

- [统一缓存清理遗漏或清得过宽] → 核对所有认证入口及私有查询，保留真正的公共设置；验证旧查询与 mutation 迟到结果不能跨身份写回。
- [busy 范围过短或永不释放] → 覆盖保存后的验证链路，校验失败/请求失败/成功分别测试解锁；不将服务器长任务整个运行期当成表单提交期。
- [凭据改为可选后误发送空值] → 前端类型、序列化和隔离 API fixture 同时验证保留、替换和认证类型变更，fixture 仅使用虚构秘密。
- [父级 Provider 改动重置其他列表或嵌套遮蔽] → Env 层集成测试覆盖双载体、多环境、日志返回、关闭重开及页码越界。
- [预加载失败或旧导航回调] → 受控延迟与拒绝测试覆盖连续选阶段、视图/项目切换、离开页面和未保存确认。
- [overview 公共边界漏状态或刷新能力] → 页面与阶段集成测试核对读取、错误/重试、缓存更新、SSE 与阶段关闭，不新增兜底订阅。
- [测量开关泄漏监听或改变滚动] → observer/resize 生命周期与三档桌面验收，不用推测的性能数字替代结果。
- [公共化引入反向依赖或视觉变化] → 检查导入路径，复用领域详情、代码定位和导航测试。
- [并行阶段迭代影响范围] → 不修改 `integrate-memory-order-and-floating-point-nodes`，后续实现前重新检查 diff，避免覆盖其他工作。

## Migration Plan

二次诊断补齐采用现有 useSubmissionSession，在表单校验前取得同步锁和所属 token，避免旧校验在新账号下开始请求。StageDrawer 的业务实例 key 包含认证 generation、projectId 和 stageId，presentation 不进入 key，因此同项目双视图不丢草稿。项目 SSE 同时订阅认证变化并同步 dispose，所有事件、刷新和重连检查 generation，effect 重启继续沿用既有订阅基线。

自动化测试由 useTestBatchSubmission 独立管理两侧创建的结果，不以 allSettled 的 Promise 完成代表业务全部成功。失败保留原批次、两侧构建输入、提交时配置及已确认任务；重试仅发送失败侧，全部成功后才调用原草稿的 markSubmitted。恢复状态仅属于当前项目、身份与编辑生命周期，不新增持久化数据或回滚已提交任务。HTTP 未确认创建不能证明服务端未执行，界面使用“未能确认创建”的表述，不宣称后端具备幂等能力。
