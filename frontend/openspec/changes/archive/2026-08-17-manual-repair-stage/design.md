## Context

当前固定 Workflow 将环境管理与源码制品管理串联，并由源码更新自动启动六条分析支路。当前确认的业务流将环境与源码视为并列的源数据：环境管理为环境与依赖对比提供可选环境，源码管理为知识库扫描提供当前源码版本；每个扫描均由用户手动执行。评估报告后需要开放人工修复，但 AI Agent 重写与源码对比内容仍不在本 change 范围内。

## Goals / Non-Goals

**Goals:**

- 在固定画布中表达“源数据管理 -> 环境扫描/源码扫描 -> 迁移输入合并 -> 评估报告 -> 人工修复 -> 源码管理”的可见业务路径。
- 使源码上传和 Git 更新只产生当前可扫描源码版本，不隐式启动扫描。
- 提供人工修复线下处理提示、最新源码对比状态与回到源码管理的闭环。

**Non-Goals:**

- 不开发 AI Agent 重写节点、自动修复、补丁或分支能力。
- 不实现源码对比 Drawer 的内容、对比计算或构建验证。
- 不自动编排或自动启动环境与依赖对比、知识库扫描、迁移输入合并和评估报告。
- 不引入源码版本历史、回滚或新的运行时依赖。

## Decisions

### 保留阶段 ID，重构展示拓扑

前端继续使用既有稳定阶段 ID：`env`、`assets`、`sbom`、`kb`、`merge`、`report` 和 `manual`；其中 `assets` 的展示名改为“源码管理”，`sbom` 改为“环境与依赖对比”。固定拓扑在前端维护，新增“源数据管理”“环境扫描”“源码扫描”分组。

原因：阶段 ID 已被 API、mock、缓存和状态快照使用，名称调整不应迫使后端迁移无业务价值的标识。组仅是 React Flow 的视觉节点，所有业务 edge 始终连接具体阶段节点：`project -> env/assets`、`env -> sbom`、`assets -> kb`、`sbom/kb -> merge`、`merge -> report`、`report -> manual`、`manual -> assets`。

备选方案是将 edge 连接到分组边界；不采用，因为分组不具备可执行阶段语义，无法表达前置条件或跳转目标。

### 项目级分析环境前置配置

环境列表继续管理可复用的远程环境资源；项目级运行环境配置单独由 `GET/PATCH /projects/{projectId}/runtime-environments` 维护。环境管理 Drawer 是唯一写入入口，在同一 Drawer 中选择启用的 x86 源环境和 RISC-V 目标环境；共享 `useProjectRuntimeEnvironments(projectId)` 仅负责读取与缓存。

环境与依赖对比不再按次选择环境，也不再向创建分析接口传递环境 ID。配置视图只读展示当前项目级配置；配置缺失时禁用开始分析并引导用户到环境管理。服务端在创建分析时再次校验项目级配置，且将当次执行使用的环境/快照固化到分析记录，避免后续更新改写历史含义。

### 所有扫描保持显式触发

源码管理成功更新当前源码后只刷新当前源码和画布状态，不调用启动分析接口。用户进入知识库扫描后手动新建或开始扫描；用户进入环境与依赖对比后手动执行或重新执行分析。迁移输入合并与报告生成也保留显式操作。

原因：用户已确认流程不使用自动触发，画布 edge 表示数据依赖和可前进路径，而非任务调度规则。

### 人工修复作为源码更新过渡页

人工修复使用独立的 Stage Drawer 调用 `GET /projects/{projectId}/source/compare/latest`，展示当前 active 源码版本、上一可比较版本、最近复检状态与线下修复提示。Drawer 不提供在线代码编辑、自动 patch、处理备注或修复记录；Footer 的主操作跳转到 `assets`，由用户提交修复后的源码。

备选方案是将上传/Git 表单嵌入人工修复 Drawer；不采用，因为源码版本的上传、凭据保护和版本有效性均属于源码管理职责。

### API、mock 与缓存边界

领域 API 模块负责最新源码对比数据；Stage Drawer 通过 TanStack Query 获取并失效对应 project/stage query。开发 mock 保持正式 `success/data/error/traceId/timestamp` 包络，并模拟无上一版本、复检未开始与源码更新成功等状态。

共享 `BaseDrawer`、`BaseTable` 不直接调用领域 API；各 Stage 模块拥有请求和状态编排。

## Risks / Trade-offs

- [旧的阶段推进接口仍假设 `env -> assets` 和源码更新后六路自动分析] → 替换 mock 与前端调用路径，并在 API 失败时展示服务端错误，不在页面层伪造流转。
- [项目级分析环境缺失、失效或被修改] → 环境与依赖对比在前端阻止提交并引导配置；服务端仍在提交时校验当前配置并固化当次使用的环境/快照。
- [当前源码不存在上一可比较版本] → 展示明确空状态并允许用户前往源码管理提交后续修复版本。

## Migration Plan

1. 将固定拓扑切换为新节点名称、分组和具体 edge，并开放 `manual` 节点、继续隐藏 `agent` 与 `diff`。
2. 调整源码管理提交后的行为，移除自动启动六项分析的调用与确认文案。
3. 新增人工修复 Drawer，接入最新源码对比 API 并提供返回源码管理入口；评估报告入口跳转至该阶段。
4. 运行格式、lint、类型、单元测试与 OpenSpec 校验。若新接口未联调，保留 mock 合约并在交付说明中标记。
