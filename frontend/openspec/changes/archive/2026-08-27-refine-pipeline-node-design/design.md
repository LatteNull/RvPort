## Context

项目流水线的画布节点是用户理解业务流和进入 Drawer 的入口。现有“项目创建”仍以一次性阶段表达，且其 footer 只有一条推进路径；环境管理又把项目级 x86/RISC-V 选择误称为“分析环境”。环境脚本的完成态日志仍按旧日志元数据接口渲染，无法利用后端已提供的正文分页接口。

本次按确认顺序实现 Node 1（项目基础配置）、Node 2（环境管理）、Node 3（源码管理）、Node 5（知识库扫描）、Node 6（x86 构建）、Node 7（依赖分析）和 Node 8（评估报告映射）。Node 4 已废弃，迁移输入汇总不再作为独立画布节点。

## Goals / Non-Goals

**Goals:**

- 让项目起始节点名称与两个实际输出入口一致。
- 让环境管理明确展示项目当前运行环境，并只从可用环境中选择。
- 使用统一的任务日志正文接口展示环境脚本的完成态日志，保留受控下载能力。
- 在不新增依赖的前提下压缩环境脚本执行记录和日志详情的视觉密度。
- 让源码管理展示当前可用源码及其 Git 分支，并避免 Drawer 重开时沿用旧记录。
- 让知识库扫描和依赖分析在风险语义、列表固定列及迁移输入入口上保持一致。
- 让 x86 构建日志适配“offset=0 为最新页”的后端日志分页协议，并保持最终日志位于编辑器底部。
- 让评估报告不直接暴露依赖分析的来源和匹配状态枚举。

**Non-Goals:**

- 不调整后端 API、workflow 状态机或后续画布节点。
- 不替换运行中任务的 SSE 日志流。
- 不改变环境脚本的执行、检查或凭据存储语义。

## Decisions

### 将项目创建表达为项目基础配置

画布 node 标题更新为“项目基础配置”，不再展示重复性的画布副标题。其 Drawer 继续复用项目详情数据，但 footer 改为两个并列导航入口：环境管理和源码管理；不再将其中任意一项误表达为唯一下一步。

### 当前运行环境为项目级复用配置

环境管理 Drawer 将“当前分析环境”改为“当前运行环境”，说明其是环境相关后续节点的共同输入。配置选择器请求环境列表时传入 `status=AVAILABLE`，并保留本地的启用/SSH 成功兜底检查，避免旧数据或服务端状态差异进入选择结果。

### 完成态日志使用正文接口

环境脚本日志以 `GET /api/tasks/{taskId}/log-content` 为数据源。默认先读取 `merged`，并按用户选择读取 `stdout`/`stderr`；每种类型单独维护 offset 与 hasMore，向上加载时将较早内容 prepend。旧 `/logs` 仅用于获取受控下载所需的日志 ID，不再用于拼接正文。

采用单一日志内容视图而非按元数据记录逐卡渲染，以避免日志 flush 数量影响页面请求和高度。

### 紧凑日志概要与可读脚本编辑器

日志页顶部采用横向摘要栏：脚本名和状态、执行摘要、提交时间、退出码、日志事件数。正文区获得主要纵向空间。执行记录表去除脚本哈希，退出码显示为普通文本。脚本编辑器继续复用现有 CodeMirror，并显式保留 gutter 行号。

### 源码管理仅查询当前有效版本

源码管理只需要当前有效版本作为后续节点输入，因此 `/sources` 查询传入 `active=true` 并限制为单条结果。Git 来源的仓库地址以新窗口链接展示，同时展示服务端返回的 `gitBranch` 与 `gitCommit`。查询在 Drawer 打开时始终重新请求，关闭时移除对应查询缓存，避免用户将过期版本误认为当前源码。

### 知识库扫描与依赖分析使用一致的风险表达

知识库扫描结果列表将“严重等级”统一称为“风险”，文件与风险固定在左侧，行号不固定。依赖分析的风险分布直接复用知识库扫描的计数分布组件；目标侧匹配与风险分布在宽屏并列展示。两类结果列表均通过行级迁移输入操作进入后续报告输入管理。

### x86 构建日志按阅读顺序拼接

后端 `log-content` 的 `offset=0` 返回最新页，且页内内容为最新到更旧。前端将每页行序反转为阅读顺序，并在取得后续页时将更旧页放到已有内容顶部。Monaco 初次加载滚动到底部，向上滚动触发加载时保留当前位置，行号始终以拼接后的阅读顺序连续编号。

### 依赖分析以结果数据为中心

依赖分析不沿用知识库扫描的发现项/阻塞项指标，而是直接展示后端返回的 `total`、`byRisk` 和 `byTargetMatchStatus`。列表将风险置于依赖名之后并固定，映射依赖类型和目标匹配状态，移除置信度、版本证据及来源位置等非列表必要信息。依赖名进入二级详情；详情只允许返回分析页，不可直接关闭 Drawer。分析制品在概览内提供下载，空结果页提供执行分析与历史记录入口。

### 评估报告兼容依赖分析输入

评估报告将 `DEPENDENCY_RESULT` 映射为“依赖分析”，并映射依赖分析全部目标侧匹配状态及 `COMMENT` 风险等级；历史报告保留旧状态映射兼容。

### 评估报告以结论和处理顺序为主

评估报告不再单独展示报告身份卡或重复的工作量说明。生成状态和时间收敛至报告概览标题区，总体风险作为有语义边界的主指标，纳入问题、高风险问题和预计工作量作为次级指标。输入来源与风险分布收敛为并列的紧凑分布区；优先处理项和依赖替代提示保留为报告的主体内容。

## Risks / Trade-offs

- [Risk] 旧任务可能不存在 merged 日志。 → Mitigation：空 merged 时展示无日志提示，并允许切换至 stdout/stderr；下载仅在对应日志 ID 存在时出现。
- [Risk] `AVAILABLE` 不完全等同于启用且 SSH 成功。 → Mitigation：保留前端候选校验，后端未来可补充更精确筛选条件。
- [Risk] 将项目基础配置 footer 改为两个入口可能与旧阶段推进接口耦合。 → Mitigation：复用已有 Drawer 导航方式；若源码管理尚不满足前置条件，保持其既有服务端/前端禁用与提示。

## Migration Plan

1. 先改 Node 1 名称与两个 footer 入口。
2. 改造环境管理文案、可选环境查询与辅助文本。
3. 增加任务日志正文 API 类型和请求函数，替换环境脚本日志页的数据源。
4. 运行单元测试、类型检查、lint 和 OpenSpec 校验；若需要回退，环境日志页可临时恢复旧元数据展示。
