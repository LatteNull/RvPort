## Why

原型中的“优化测试”分组已经把“自动化测试”定义为构建后的首个可执行节点，但当前项目将该节点标记为延后实现，点击后也没有专用 Drawer。后端已经具备按构建产物分别在 x86 与 RISC-V 环境执行测试、并自动生成结果对比的能力，前端尚未把这条闭环交付给用户。

## What Changes

- 将“自动化测试”作为构建后的可执行流水线节点，并提供专用 Drawer。
- 以当前源码在两个环境中成功完成的构建作为测试前置条件；用户不再选择环境或任意构建记录。
- 让用户配置一套共享测试命令、超时和环境变量，并用同一个批次标识提交 x86 与 RISC-V 两个测试运行。
- 展示两个环境各自的测试状态、聚合结果、构建目录、日志入口和历史记录；运行中的任务可取消。
- 展示后端自动触发的测试结果对比及其不可用原因，不提供手动对比或“仅重跑失败用例”。

## Capabilities

### New Capabilities

- `automated-test-stage`: 在项目流水线中执行、跟踪并比较同一当前源码的 x86/RISC-V 自动化测试批次。

## Impact

- 前端：项目详情的流水线拓扑、Stage Drawer 路由、项目 API 类型与请求封装、查询失效策略和测试覆盖。
- 后端：复用现有 automated-test、task-log 与 test-comparison 接口；本变更不新增服务端数据模型或接口。
- 用户体验：测试执行从“原型中的待实现节点”变为可操作的构建后步骤，Benchmark、性能剖析与 RVV 测试仍保持后续范围。
