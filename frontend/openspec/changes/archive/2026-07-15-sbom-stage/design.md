## Context

SBOM 是源码制品阶段启动的并行分析支路。现有工作台仅能显示节点状态，无法查看组件替代结论或将选中的结论交给迁移输入合并。

## Goals / Non-Goals

**Goals:**

- 在 `sbom` 节点提供专属 Drawer，按运行、完成、失败状态展示 SBOM 任务。
- 完成态以统计和可选择的替代结果表为主体；表格工具栏提交已选项，Footer 重新分析整个任务。

**Non-Goals:**

- 不在结果页重复展示环境、源码制品或分析配置快照。
- 不自动推进 `merge`，不实现报告导出、采集详情和实时 SSE。

## Decisions

### 1. 结果页与配置视图分离

结果页只显示 x86 组件、RISC-V 候选、无替代组件统计和结果表。x86/RISC-V 环境、软件源策略、采集范围和分析选项仅在执行或重新分析的 Modal 中配置，避免压缩结果表空间。

### 2. 表格选择只服务迁移输入

`全选`、已选数量和“加入迁移输入”位于表格工具栏；提交前必须至少选择一项并二次确认。重新分析不使用当前选择，作为 Footer 的阶段级操作执行并覆盖当前结果。

### 3. 服务端任务为状态事实来源

详情、组件结果、创建分析、加入迁移输入均通过领域 API 与 TanStack Query 管理。创建或重新分析后由服务端返回 workflow/任务状态；本 change 不建立 SSE。

## Risks / Trade-offs

- [任务运行期间缺少实时事件] → 显示服务端返回的最近状态，后续统一任务事件 change 再接入 SSE。
- [结果表列较多] → 使用 Ant Design Table 的横向滚动与固定选择列，不隐藏关键列。
- [重新分析覆盖选择状态] → 确认弹窗明确说明会覆盖当前结果和选择。
