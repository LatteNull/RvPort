## Context

当前共享 `TaskLogPanel` 和环境脚本日志视图使用 `log-content` 的倒序 offset 分页，该接口适合任务完成后的日志文件，但在文件持续增长时 offset 不稳定。后端已提供 `log-notifications` 作为轻量唤醒通道，并提供基于 `task_log_events.id` 的 `log-increments` 前向游标读取；一次增量响应同时包含 `merged`、`stdout`、`stderr`。

项目已有项目级 SSE 的连接、退避与清理实现，但任务日志需要独立连接，并且通知事件不能被解释为正文已成功消费。实现还需符合项目约束：服务端请求状态通过 TanStack Query 管理、页面不复制实时连接逻辑、日志正文不持久化、Monaco 继续按需加载。

## Goals / Non-Goals

**Goals:**

- 建立可复用的任务日志数据边界，为所有日志页面提供一致的运行态与完成态模型。
- 以最后一次成功增量响应推进游标，支持重连、补拉、终态收尾和失败恢复。
- 保持运行中日志接近实时，同时限制浏览器内存和 Monaco 渲染规模。
- 保留完成态日志文件的倒序分页、向上加载和下载行为。

**Non-Goals:**

- 不修改后端接口、5 秒通知周期、日志事件存储或终态集合。
- 不接入已废弃的 `/log-events` 正文 SSE。
- 不持久化实时日志正文或游标，也不在本 change 中提供跨页面保留阅读位置。
- 不改变 Monaco 的通用编辑器交互和视觉设计。

## Decisions

### 1. 使用单一任务日志控制器组合两种后端语义

新增页面领域 Hook 作为任务日志控制器，输入 `taskId`、任务状态和启用条件，输出统一的三类日志内容、连接状态、读取状态、错误、截断状态和重试操作。运行态由通知 SSE 唤醒增量 query；终态由现有无限分页 query 读取日志文件。

控制器属于项目详情领域而非通用视觉组件：它了解 RvPort 任务状态和 API，但 Monaco/LogViewer 只接收展示数据。`TaskLogPanel` 负责组合控制器和日志界面，环境脚本日志也复用同一控制器，避免第二套连接实现。

备选方案是让每个页面分别接入 SSE，风险是重连、游标和终态处理很快出现差异，因此不采用。

### 2. 增量请求使用 TanStack Query mutation 驱动，游标与追加状态由 reducer 管理

增量读取是事件驱动的命令式追加，不适合把不断变化的 cursor 放进普通 query key。Hook 使用 mutation 管理每次 HTTP 请求的服务端生命周期，以 reducer 保存当前 task 会话的三类缓冲、成功游标、目标终态游标和截断信息；连接状态与定时器保存在局部 state/ref 中。

所有读取通过一个 drain 调度器串行执行。通知到达时只提高待消费目标并触发 drain；若已有请求进行中则复用该执行链。只有成功响应才追加正文和更新 cursor；`hasMore=true` 或通知的目标游标尚未达到时继续读取。

备选方案是 `useInfiniteQuery` 直接表达增量批次，但事件唤醒、失败重试和三类并行缓存会让 pageParam 与 query 重取语义混乱，因此只将 `useInfiniteQuery` 保留给完成态 offset 分页。

### 3. SSE 是唤醒信号，不是消费确认

连接 URL 始终携带当前成功 cursor，并使用 Cookie Session 的 `withCredentials`。连接建立后无论是否收到 updated 都主动 drain 一次，以覆盖建立窗口和通知丢失。收到 `task.log.updated` 时记录服务端 `latestEventId` 并触发 drain，但不直接修改成功 cursor。

连接错误采用与项目级 SSE 一致的指数退避。增量 HTTP 失败单独重试，因为同一连接不会保证重复通知同一个未成功消费的事件；用户也可通过日志工具栏立即重试。页面从隐藏恢复可见时再主动 drain。

### 4. 终态采用“补拉后替换”而非拼接两种来源

收到 `task.log.completed` 后保存其 `latestEventId`，继续 drain 至目标游标且 `hasMore=false`，随后触发任务/领域数据刷新。调用方传入状态转为终态后，控制器关闭 SSE，并启用 `log-content` 的第一页读取。

完成态第一页成功后直接替换实时缓冲的展示来源，不把文件内容追加到事件内容，避免重复。若完成态文件尚未落盘或首次读取失败，界面暂时保留已经取得的实时日志并显示可重试状态，避免终态瞬间出现空白。

直接打开终态任务时跳过 SSE 和增量读取，直接走现有历史分页。

### 5. 一次增量响应维护三个本地缓冲

每次响应同时追加 `merged`、`stdout`、`stderr`，Tab 切换只改变展示选择，不发请求、不重建连接。这样游标只存在一份，不会因用户未打开某个 Tab 而遗漏该类型内容。

运行态每类缓冲采用字符与行数共同限制，默认最多保留 20,000 行且不超过 4 MiB；超出时从最早完整行开始裁剪并设置 `truncated=true`。限制是展示资源边界，不影响 cursor。完成态仍通过每页 100 行向上读取完整历史。

### 6. query key 归入领域工厂，任务切换执行完整清理

完成态日志 query key 统一由项目领域 query-key 工厂按 `taskId` 和内容类型生成，不再由调用方传入任意字符串。任务 ID 改变或组件卸载时，清理 EventSource、重连计时器、HTTP 重试计时器和当前会话缓冲；不写入 localStorage/sessionStorage。

## Risks / Trade-offs

- [风险] 任务终态状态刷新慢于 completed 通知，界面会短暂保留实时模式。 → completed 后立即刷新任务和领域 query，并在等待期间保留最后日志与“正在整理最终日志”状态。
- [风险] 事件日志和最终文件短时间不一致。 → 终态文件成功加载后以 `log-content` 为权威；文件未就绪时保留实时内容并允许重试。
- [风险] 频繁小批增量导致 Monaco 反复更新和自动滚动。 → 合并同一 drain 周期的响应后批量提交状态；仅当用户原本位于底部时跟随最新内容。
- [风险] 运行任务较多时打开多个日志产生多个 SSE。 → 只为当前可见日志视图建立任务级连接，离开立即释放。
- [风险] 截断使运行期间无法查看最早内容。 → 显示省略提示，终态后通过历史分页恢复完整访问。

## Migration Plan

1. 增加日志通知、增量接口类型和 API 契约测试。
2. 实现任务日志控制器及纯 reducer/drain 测试。
3. 改造 `TaskLogPanel` 并接入普通构建、x86 构建和自动化测试。
4. 将环境脚本日志迁移到同一控制器。
5. 验证运行态、断线、失败、终态和长日志场景；保留旧完成态路径作为可回滚边界。

回滚时可让日志面板恢复仅使用 `log-content`，无需后端或数据迁移；旧 `/log-events` 不进入新实现。
