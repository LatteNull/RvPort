## Context

见 `proposal.md`。当前 React Router 已将页面拆分为懒加载路由，`StageDrawer` 也已按阶段动态导入；Monaco 已通过 `lazy()` 和共享 Promise 按需下载。CodeMirror 的静态依赖会在包含它的 Drawer chunk 解析时下载，即使当前 Drawer 视图尚未显示编辑器。`CodeMirrorEditor` 的默认数组 props 会使其 memo 化扩展重建；表格尺寸测量也会在相同高度上重复 setState。认证背景按产品要求保持现状。

## Goals / Non-Goals

**Goals:**

- 在保留现有编辑和日志交互的前提下减少不必要的网络、解析和渲染开销。
- 让重型编辑器只在用户实际进入需要它的视图时下载，并提供不阻塞交互的加载反馈。
- 将优化结果以生产构建产物和自动化测试验证，而非只依赖代码审阅。

**Non-Goals:**

- 不替换 Ant Design、React Flow、CodeMirror 或 Monaco，不新增运行时依赖。
- 不压缩、替换或改变当前认证背景资源。
- 不改变路由、API 调用、日志分页、表单字段或业务状态机。
- 不对未测得热点的组件进行全量 `memo` 化或导入路径机械重写。

## Decisions

### 将 CodeMirror 外壳与编辑器实现分离

保留调用方的 `CodeMirrorEditor` API，但把依赖 `@uiw/react-codemirror` 和语言包的实现置于 `lazy()` 边界内；仅当组件实际渲染时加载，并以稳定尺寸的占位内容避免布局跳动。不会提前把所有编辑器预加载到项目页：仅对用户明确打开且高度可能使用编辑器的路径预加载，避免把低频依赖带入普通浏览。

### 优先修复确定的重复工作

将非原始默认 props 提升到模块常量，并确保高亮扩展只在内容或高亮行真正变化时重建；表格测量在计算结果与已有状态一致时不触发更新。React Compiler 已启用，因此不额外添加广泛的 `useMemo`/`memo` 包装；只修复其无法消除的引用不稳定和 DOM 测量反馈。

### 以构建产物和触发行为验证，而非硬编码通用大小阈值

记录此次优化前后的资源大小，并在测试中断言认证页不再引用原始超大资源、编辑器模块仅在渲染编辑器时请求。固定的全应用 chunk 阈值容易因 Vite、Ant Design 或 sourcemap 变化产生无效失败；对已识别资源采用目标性断言和生产构建复核更可靠。

## Risks / Trade-offs

- [Risk] 编辑器异步加载首次打开会出现短暂占位。→ Mitigation：使用与编辑区相同高度的加载占位，并只在明确的 Drawer 交互后启动加载。
- [Risk] 语言扩展拆分可能引入编辑器配置顺序问题。→ Mitigation：保留既有语言和高亮行为，并为每种已支持语言补充组件测试。

## Migration Plan

1. 建立编辑器延迟加载测试，记录当前生产构建基线。
2. 拆分 CodeMirror 实现并修复稳定性问题。
3. 运行质量检查、单元测试与生产构建；如出现编辑器加载故障，可回退到原同步实现而不影响 API 或数据。
