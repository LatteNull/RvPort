## Decisions

### 1. 默认展示分为两套

| 类型              | 步骤                                                                     | 默认结构                                                   |
| ----------------- | ------------------------------------------------------------------------ | ---------------------------------------------------------- |
| 条件＋记录型（A） | x86 构建、构建验证、自动化测试                                           | 当前前置条件 → 条件满足时的执行配置 → 跨源码版本的历史记录 |
| 当前概览型（B）   | 依赖分析、知识库分析、内存序分析、浮点分析、评估报告、迭代优化、项目归档 | 一个当前主状态或业务结果区 ＋ 固定的历史入口               |
| 独立展示（I）     | 项目基础配置、环境管理、源码管理、人工修复                               | 原有配置、资源管理或修复指导界面                           |

自动化测试最终确定属于 A，以测试批次作为记录单元，批次内保留 SOURCE、TARGET 测试及比较结果。迭代优化属于 B，但它是被动聚合，不新增“开始优化”操作。

### 2. 当前条件与历史事实分开

readiness 表达当前是否具备新执行条件；latest 的 execution 表达执行事实，freshness 表达结果是否适用于当前上下文；历史列表/详情表达各记录自身事实。Workflow 节点状态不能替代 readiness，也不能用 readiness 覆盖真实已完成或运行状态。

历史记录默认跨源码版本，按创建时间倒序分页，标明记录所属源码版本及必要的环境信息。当前源码切换、当前条件受阻、readiness/latest 请求失败，都不能阻断历史阅读。无记录与已有筛选无结果分别表达。暂不新增源码版本筛选；现有其他筛选不在本次讨论中一并移除。

构建、依赖分析、知识库列表后端默认 `currentOnly=true`。历史查询需按接口支持显式使用 `includeStale=true` 或 `currentOnly=false`，并移除自动绑定当前源码/环境的限制；仅删除 `sourceRevisionId` 不足以实现跨版本历史。用于计算当前门禁或选取测试输入的查询仍保留当前上下文约束，不能与历史查询混用。其他列表按各自真实契约处理，不盲加不存在的参数。

### 3. A：条件、配置和记录相互独立

当前条件未满足时展示原因和恢复入口，隐藏执行配置；历史记录仍然展示。条件满足时显示执行配置和开始操作，历史仍在下方。

已有任务运行时，记录保留真实状态，不额外增加“有任何运行任务就禁用新建”的前端规则。新建依据当前服务端执行条件；提交请求期间防止重复点击，失败后保留配置。后端若拒绝创建，明确展示原因，不能绕过接口限制。自动化测试门禁存在已确认的契约问题，修复前不宣称该能力已经可用。

记录逐条显示等待、排队、运行、成功、失败、取消或超时。取消等控制仅保留现有接口支持的运行任务操作；进入历史详情后只读，不增加隐含创建任务的“重试”。测试批次部分提交失败应保留已创建任务，并保留仅补交失败侧的既有处理，不能整批重复提交。

### 4. B：当前条件优先，保留执行事实

状态优先级和完整组合见矩阵 B01–B14。核心规则：

1. 首次读取没有数据时显示加载；首次读取失败显示重新加载。后台刷新失败保留已有内容并轻量提示；无法确认门禁时暂停新执行。
2. 当前条件未满足时只显示一个受阻主状态，列出全部相关阻碍和恢复入口。旧成功或失败结果从历史查看，不与当前受阻状态并列竞争。
3. 若条件受阻但真实任务仍在运行，以辅助信息保留该任务身份、所属版本及日志/记录入口，不推断它已经取消或失败。
4. 条件满足且没有当前有效结果（EMPTY 或只有 STALE 终态）时，展示就绪引导、已满足的前置条件和开始操作。旧结果通过历史入口查看；STALE 不显示成当前成功。
5. 已提交但服务端状态尚未同步时显示“已提交，正在同步状态”，避免短暂回到可执行空态。PENDING、QUEUED、RUNNING 期间均不提供再次执行入口。切换源码后仍能确认旧任务活动时，也保留其事实并遵循此限制。
6. 当前失败、取消、超时分别表达，提供日志/详情；当前条件允许时提供重新执行。当前成功保留该模块完整业务结果和必要的源码、环境、时间信息，不重复展开整套已满足条件。
7. 成功但无风险、部分分析不完整、没有记录是不同状态，不能统一成“暂无数据”。

B 的历史入口固定在内容标题区右上方，贯穿加载、请求失败、受阻、就绪、运行及结果状态；模块代码尚在懒加载时沿用容器加载态。进入历史以后，仅由历史查询控制页面状态。历史详情只读，按真实来路返回历史列表或当前概览，并保留原有详情子层级。

B 运行期间不提供再次执行入口是已确认的产品规则，不意味着后端已经实现跨标签页或多客户端互斥。

### 5. 前置条件和操作语义统一

以 prerequisite `key` 映射条件名称和恢复目标，以 `status` 表达未满足、运行中、失败或不可用。`reasonCode` 可以补充原因，不用于决定条件标题或跳转目标。各模块仅展示自身实际需要的条件，不复制一套虚构通用条件。

四项分析的 x86 构建提示统一为未完成、正在构建、构建失败或已满足等明确语义，按服务端具体状态区分；恢复入口指向 x86 构建。其他未满足项也要保留，不只显示第一条。工具服务不可用时提供原因和刷新，不能把基础设施问题伪装成可通过项目配置解决。

“重新加载”重读数据，“重新执行”创建任务，“查看日志/详情/历史”只读。每个主要状态或操作区域至多一个主操作，多个条件的恢复跳转使用次要入口。

### 6. 样式沿用现有体系，做局部统一

| 项目       | 已确认方向                                                                                                |
| ---------- | --------------------------------------------------------------------------------------------------------- |
| A 页面结构 | 条件和配置保持左对齐、紧凑排列，下方接记录；不增加大幅居中空态                                            |
| 前置条件区 | 减弱大面积绿色/橙色渐变与描边，使用轻柔底色、图标和简短结论表达状态                                       |
| B 主状态   | 继续复用居中 `StageStateNotice`，统一同类状态的最小高度、上下留白与文本宽度；成功业务内容自然展开         |

| 文本       | 关键条件、失败原因完整换行，不因省略号隐藏阻碍；恢复操作紧邻对应条件                                      |
| 操作层级   | 开始/重新执行为主操作；历史、日志、详情为次要链接或文本操作；B 历史位置固定                               |

| 视觉基础   | 沿用 `STYLE_GUIDE.md` 的字体、间距和主题 token，保留已有 ContentState 降权修改，不新增装饰性卡片/边框矩阵 |

### 7. 实现边界与后端依赖

领域适配负责读取 readiness/latest/记录并提供事实，纯展示逻辑负责状态组合；优先复用 `StageStateNotice`、`ContentState`、记录标题等，不建立承载全部领域 hook 的巨型控制器，不跨阶段引用内部组件。

保留既有 Drawer/面板和二级内容容器、关闭/返回行为，不新增第三种页面层级。当前和历史查询分离，历史视图不依赖当前观察者；刷新所有权遵循 `project-stage-runtime` 的项目事件/SSE 边界，mutation 仅报告提交，不另起一套竞争刷新链。

后端交接分为两类：测试、知识库、专项分析、报告的门禁契约不一致需要对齐；共享工作目录的构建/测试并发隔离、latest 选择语义需要后端确认。前端不得通过忽略 readiness、伪造状态或扩大禁用范围掩盖这些问题。具体证据和验收诉求见后端交接文案。

## 实施顺序与验证

1. 以矩阵为清单，先复核当前差异及后端反馈；必要的阶段专属规范变化先进入本 change 的 delta。
2. 先实现 A 的条件/记录独立读取、跨版本历史和测试批次默认列表，再实现 B 的状态解析、统一历史入口及只读返回。
3. 对齐同一条件的文案、恢复入口及样式，逐模块保留业务结果内容。
4. 用矩阵场景建立有意义的回归测试，特别覆盖受阻与运行并存、旧结果、提交同步、历史独立、部分批次失败和刷新失败。
5. 代码实施后按 `openspec/project.md` 完成格式、lint、typecheck、全量非 watch 测试及适用构建验证，并在真实已登录浏览器检查两种视图、返回、布局与状态组合。隔离 fixture 通过不能写成真实业务验收通过。

前端实现期间执行相应工程门禁与浏览器只读验收；不创建真实业务任务。矩阵中的场景逐项记录验证范围。Bitcode v2 制品生成不属于本 change 的完成条件；后端相关契约限制单列记录。
