## 2. 组合维度及解析顺序

| 维度      | 值及用途                                                                         | 不得混淆                                                     |
| --------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 视图      | 当前 / 历史列表 / 记录详情 / 领域子详情                                          | 历史页面不使用当前门禁决定可读性                             |
| 请求      | 首读加载、首读失败、已有数据刷新、刷新失败                                       | 请求失败不等于任务失败                                       |
| readiness | 所需项 SATISFIED 或未满足/运行/失败/不可用                                       | 只采用该操作实际需要的项，不把所有信息项视作硬门禁           |
| execution | PENDING、QUEUED、RUNNING、SUCCEEDED、FAILED、CANCELLED、TIMED_OUT 等接口实际枚举 | 用领域类型适配状态，execution 有值而 result 尚无值也必须展示 |
| freshness | CURRENT、STALE、EMPTY                                                            | STALE 表示上下文不适用，不意味着记录失败或被删除             |
| 记录      | 无记录、有记录、筛选无结果、分页/详情错误                                        | 当前没有结果不等于整个项目没有历史                           |
| 提交      | 未提交、提交中、部分提交失败、已受理待同步、拒绝/失败                            | 仅受理不代表任务已开始或成功                                 |

先选择视图；历史按第 5 节独立解析。当前视图先处理无数据请求状态，再将已知门禁、真实活动任务、freshness 和终态组合。后台刷新保留内容；门禁不能确认时禁用新执行。A 的记录区域始终独立，B 的历史入口始终保留。取消、超时等名称遵循实际领域枚举，不新增服务端不存在的状态。

## 3. A：条件＋记录型全状态矩阵

适用 x86-build、build、test。以下记录区规则与任意当前条件组合均成立。

| 编号 | 当前事实                        | 条件/配置区                                            | 记录区                                     | 操作及刷新                                           |
| ---- | ------------------------------- | ------------------------------------------------------ | ------------------------------------------ | ---------------------------------------------------- |
| A01  | 首次读取条件，尚无数据          | 局部加载，不出现可执行配置                             | 独立加载或展示已取得记录                   | 当前不可提交；列表不等待条件完成                     |
| A02  | 条件读取失败，无可用数据        | 条件错误及重新加载                                     | 不受影响                                   | 重读当前条件，不清空列表                             |
| A03  | 所需条件未满足，无论有无旧终态  | 列出原因及恢复入口，隐藏执行配置                       | 展示全部记录或真正无记录态                 | 前往对应步骤为次要操作；无新执行                     |
| A04  | 条件满足，无历史                | 条件摘要＋执行配置                                     | “暂无执行记录”（测试为批次）               | 开始为主操作                                         |
| A05  | 条件满足，有历史/只有旧版本结果 | 当前条件＋配置                                         | 保留跨版本记录及版本标签                   | 允许依据当前条件新建；旧成功不替代当前门禁           |
| A06  | 已有排队/运行记录               | 按当前条件决定能否创建，不额外全局锁定                 | 每条显示自己的真实状态和可用日志           | 允许时保留开始；现有取消能力按记录状态与接口决定     |
| A07  | 上游变化导致受阻，旧任务仍运行  | 按 A03                                                 | 旧任务继续显示运行及所属版本               | 不推断取消/失败；等待事件更新真实状态                |
| A08  | 正在提交 / 已受理待同步         | 提交期间按钮 loading、防重复点击；已受理后提示正在同步 | 已确认任务身份可用于待同步提示，不伪造成功 | 由服务端事实更新列表；A 不将整个运行期变成禁止创建期 |
| A09  | 创建失败 / 测试部分提交失败     | 保留用户配置，显示提交错误                             | 已成功创建的记录保留                       | 普通失败可再次提交；部分批次仅补交失败侧，详见 D02   |
| A10  | 后台刷新失败                    | 保留条件/配置并轻量提示；门禁未知暂停提交              | 列表按自身刷新状态保留已有记录             | 刷新恢复后按最新门禁判断；不展示整页失败             |

### A 的记录状态

| 记录状态           | 展示                                                 | 操作                                 |
| ------------------ | ---------------------------------------------------- | ------------------------------------ |
| 等待/排队          | 真实状态、版本、提交时间；无进度时不编造百分比       | 详情/日志；取消仅限既有能力          |
| 运行               | 执行事实、时间、已有进度和输出                       | 详情/日志；支持时取消                |
| 成功               | 业务摘要；x86 与构建验证按各自 scope，测试按批次聚合 | 详情及已有制品/比较入口              |
| 失败               | 失败原因、时间；不能显示为“请求失败”                 | 详情/日志；重新创建在当前配置区进行  |
| 取消               | 已取消、时间及已有原因                               | 只读详情/日志                        |
| 超时               | 执行超时、时间及已有原因                             | 只读详情/日志                        |
| 旧源码或旧环境记录 | 上述真实状态＋明确上下文                             | 只读历史；不因旧版本隐藏或伪装成当前 |

## 4. B：当前概览型全状态矩阵

适用七个 B 步骤。除 optimize 被动聚合例外外，以下规则完整适用。历史入口固定在标题区右上方，是次要操作，每行均保留。

| 编号 | 组合条件                                           | 主展示                                                       | 辅助信息                                   | 主操作 / 次要操作                                                 |
| ---- | -------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------ | ----------------------------------------------------------------- |
| B01  | 首次读取无数据                                     | 当前概览加载                                                 | 不伪造就绪或无结果                         | 无 / 历史                                                         |
| B02  | 首次读取失败无数据                                 | 当前状态加载失败                                             | 真实请求错误                               | 重新加载 / 历史                                                   |
| B03  | 后台刷新中或失败，有内容                           | 保留原内容；失败轻量提示                                     | 标明刷新未成功，不能冒充最新               | 门禁不确定暂停新执行 / 刷新、历史及可用只读入口                   |
| B04  | 受阻＋EMPTY                                        | 一个前置受阻状态，列全部阻碍                                 | 各条件原因和恢复目标                       | 不执行 / 恢复跳转、历史                                           |
| B05  | 受阻＋旧成功/失败/取消/超时（CURRENT 或 STALE）    | 同 B04，不叠加完整旧状态卡片                                 | 可简短提示有历史记录                       | 不执行 / 恢复跳转、历史                                           |
| B06  | 受阻＋真实活动任务                                 | 同 B04                                                       | 一条任务运行事实，任务身份、版本及日志入口 | 不执行 / 恢复跳转、任务详情/日志、历史                            |
| B07  | 满足＋EMPTY                                        | 已就绪，尚未执行                                             | 已满足前置条件列表                         | 开始 / 历史                                                       |
| B08  | 满足＋只有 STALE 终态                              | 当前版本暂无有效结果                                         | 已满足前置条件；说明旧结果可从历史查看     | 开始 / 历史                                                       |
| B09  | 提交中 / 已受理未同步                              | 正在提交 / 已提交，正在同步状态                              | 仅展示已经确认的任务信息                   | 不重复提交 / 历史及已可用日志                                     |
| B10  | 满足＋PENDING/QUEUED/RUNNING，含已知旧版本活动任务 | 当前任务等待/排队/执行；旧任务明确标识版本，不能充当当前结果 | 真实进度、时间或排队说明                   | 无再次执行 / 详情、日志、历史                                     |
| B11  | 满足＋CURRENT 失败/取消/超时                       | 对应终态及真实原因                                           | 时间、上下文；失败、取消、超时分别表达     | 重新执行 / 日志、详情、历史                                       |
| B12  | 满足＋CURRENT 成功且有结果                         | 模块业务结果页面                                             | 版本、环境、时间；不重复整套已满足条件     | 按模块保留一个主要业务操作，允许时可重新执行 / 历史、详情、日志等 |
| B13  | 满足＋成功但无问题 / 部分不完整                    | “未发现问题”结果 / 明确范围与不完整原因                      | 两者不能混为无数据；完整性来自领域结果     | 依领域允许重新执行 / 详情、日志、历史                             |
| B14  | 提交被拒绝或失败                                   | 保留提交前有效内容并显示错误                                 | 展示后端拒绝原因；必要时重新确认条件       | 条件重新确认后可重试 / 历史、重新加载                             |

优先级补充：有真实活动任务时不套用“只有旧终态”的 B08；没有任务事实时不能从节点颜色推断运行。若后端未提供旧版本活动任务，前端不根据猜测假装存在，也不能承诺服务端全局互斥。成功业务内容暂未返回时展示结果同步/读取状态；具体领域结果请求失败仍是读取失败，不将任务 SUCCEEDED 改成 FAILED。

## 5. 历史、详情和返回矩阵

A 为默认记录区，B 为固定入口进入的历史列表。历史请求只依赖项目、记录 ID、明确的列表参数，不依赖当前 readiness/latest 是否成功。

| 编号 | 场景                       | 展示与操作                                                                            | 当前视图关系                                                   |
| ---- | -------------------------- | ------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| H01  | 列表首读                   | 列表自身加载                                                                          | 当前条件可独立展示/失败                                        |
| H02  | 列表首读错误               | 列表错误及重载列表                                                                    | 不替换整个当前页面，不触发新任务                               |
| H03  | 项目真正没有记录           | 说明尚无历史记录                                                                      | A 条件满足仍可配置；B 返回当前                                 |
| H04  | 现有筛选无结果             | 筛选无结果及清除现有筛选                                                              | 不写成从未执行；不新增版本筛选                                 |
| H05  | 多版本、多页记录           | 时间倒序、分页、版本标识；批次见 D01                                                  | 切换源码不清空项目历史；分页错误保留可用内容                   |
| H06  | 详情首读 / 错误 / 不可访问 | 详情加载或明确读取错误，重载/返回                                                     | 当前门禁、latest 错误不遮挡；权限失效交给既有会话/权限边界     |
| H07  | 详情与日志正常             | 展示记录自身状态、输入、结果、已有制品/日志；只读                                     | 不新增重新执行、加入当前报告等修改动作；回到当前后再按门禁执行 |
| H08  | 返回与刷新                 | 详情返回真实来源；子详情返回父详情；返回列表保留分页/已有筛选；后台刷新保留已展示内容 | 从列表进入则回列表，从当前概览进入则回当前，不一律跳概览       |

历史上下文按记录本身呈现；没有版本名称时展示可用 ID/标识，不错误使用当前版本名称。只读不禁止下载或查看。A 列表中既有运行任务取消是单独的任务控制，不扩展到历史详情。

## 10. 实施中确认的接口边界

- 知识库历史接口不支持 createdAt 排序；本轮按其支持的 startedAt 倒序读取。不能将该排序宣称为严格创建时间排序，需要后端扩展后才能完全对齐。
- 自动化测试现有列表支持 createdAt 倒序但不返回 createdAt 字段；保持服务端排序，读取全部分页后按批次首次出现顺序聚合，再做批次分页。沿用既有完整聚合请求；规模增大时应由后端提供批次分页，而非前端只聚合一页。
