## Context

参见 `proposal.md` 的 Why。当前文件上下文接口已经按顺序返回 `CODE` 与 `OMITTED` block，前端却只收集所有 `CODE.lines` 并按真实行号排序后拼成单一文本，导致不连续源码在 Monaco 中视觉相邻。`OMITTED` 只在编辑器顶部形成按钮，且大于 2000 行的区间会在请求前截断、请求后却整体标记为已加载。

模块和文件详情使用 `Segmented` 渲染服务端动态问题类型；远程列表搜索分别采用 BaseTable 输入即请求和评估报告显式按钮提交两套模式。报告展示函数还在使用部分旧模块依据枚举，未知 Finding 类型仅做英文小写化。

## Goals / Non-Goals

**Goals:**

- 保留单一 Monaco 实例、真实行号、语法高亮和 Finding 聚焦能力，同时原位表达源码断点。
- 让动态类型筛选、远程搜索和多行列表项在不同页面保持一致行为。
- 只调整后端事实的展示顺序与文案，不生成新的业务结论。

**Non-Goals:**

- 不修改评估报告、文件上下文或模块组织后端接口。
- 不改变模块识别、Finding 分类、风险计算或文件筛选的服务端规则。
- 不兼容开发阶段已经废弃的旧报告组织数据。
- 不引入新的 UI、编辑器或防抖依赖。

## Decisions

### 使用 Monaco View Zone 表达省略区间

扩展共享 Monaco 封装，使其接收与编辑器模型行位置关联的只读间隔描述，并通过 Monaco View Zone 在相邻代码片段之间渲染省略行数、真实范围、加载状态和操作。View Zone 不进入文本模型，因此不会污染复制内容、语法高亮或真实源码行号。

评估报告特性层负责把接口 block 和已加载范围转换为连续代码行及剩余间隔；共享 Monaco 只负责渲染间隔并回调操作，不请求领域 API。相比插入伪代码行，该方案符合后端“省略提示不得伪装成源码”的契约；相比为每个 block 创建独立 Monaco，它保留单一滚动容器和 Finding 定位。

### 以区间差集维护分批加载状态

每个 `OMITTED` block 使用真实起止行描述未加载区间。单次请求最多读取 2000 行，响应成功后按实际返回的 `CODE` block 起止行从未加载区间中扣除；若仍有剩余范围，继续生成 View Zone。加载失败只标记当前请求范围并保留重试入口，不清除已成功加载的源码。

### 动态问题类型统一使用 Select

模块详情与文件详情统一使用可搜索 Select，选项按数量降序展示“中文类型 + 数量”，默认项为全部问题。即使只有一种类型，也保留“全部/该类型”的选择器，使问题类型始终承担一致的筛选职责。相比横向滚动或自动换行的 `Segmented`，Select 对数量和名称长度没有固定上限，也不会挤占文件工作区高度。

模块文件接口暂时沿用现有 `keyword` 参数传递选中的类型标识，文件 Finding 接口继续使用 `findingType`。本 change 不改变后端筛选契约。

### 提供共享的防抖搜索输入

新增无领域依赖的共享搜索输入，内部维护草稿值并向调用方提交规范化关键词：输入停止 300ms 后提交，Enter 立即提交，清空立即提交空值。BaseTable 的 `search` 字段和评估报告模块搜索共同复用该组件；调用方继续拥有分页重置和领域查询。

搜索框使用前置图标和清除入口，不使用主色提交按钮。这样保留搜索的辅助工具层级，并消除 BaseTable 每次按键立即创建远程查询的问题。

### 用排版层级替代等权指标矩阵

报告概览保留总体风险和全部后端计数字段，但将代码问题作为主要数字，其余事实以较低权重排列。模块行保留左侧类型分布，右侧只突出代码问题和影响文件，移除重复的类型数量。任何组合文案都不得描述“问题分布在若干模块、若干文件”等前端推导结论。

文件列表采用首行锚定布局：图标、路径首行、右侧统计和操作从顶部对齐；副标题缩进到路径起始位置。路径最多显示两行并允许在路径分隔符附近换行，超出后截断并保留完整可访问名称。

### 规范化后再映射业务文案

展示函数先把大小写、空格、下划线和连字符统一为稳定 token，再查询集中映射。模块依据只维护后端当前枚举；已知 Finding 类型（包括 `X86_COMMENT_HINT`）提供中文文案。未知动态类型使用清理后的原始值作为降级，不返回空白，也不自行推断中文含义。

## Risks / Trade-offs

- [Monaco View Zone DOM 需要手动管理生命周期] → 在共享组件内集中创建、更新和释放 zone 与事件监听，并补充卸载及重复渲染测试。
- [大区间多次加载导致模型频繁更新] → 每次按接口上限顺序加载，使用真实行号去重并保持当前滚动和 Finding 聚焦位置。
- [搜索防抖改变 BaseTable 当前即时请求节奏] → Enter 和清空保持立即生效，并为防抖、取消旧定时器与外部重置补充 fake-timer 测试。
- [动态类型存在未知值] → 已知值中文化，未知值保留可辨识原文，不阻断筛选与统计。

## Migration Plan

1. 先扩展共享搜索输入和 Monaco 间隔能力，并通过组件测试锁定通用契约。
2. 接入评估报告的 block 转换、类型选择、统计层级、列表对齐和映射。
3. 将 BaseTable 搜索字段切换到共享搜索输入，验证知识库扫描结果等现有调用方。
4. 通过相关页面测试、类型检查、lint、格式检查和 OpenSpec 严格校验；出现问题时可分别回退共享组件接入，不涉及数据迁移。
