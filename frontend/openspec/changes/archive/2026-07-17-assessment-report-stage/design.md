## Context

`migration-input-merge-stage` 在没有待处理冲突且存在已确认迁移输入时首次生成评估报告，并将 Workflow 推进至 `report`。当前 `report` 节点没有专属 Drawer，用户无法查看风险结论、导出文件或进入修复阶段。

本 change 消费服务端当前报告结果，不再访问、选择或修改迁移输入。报告历史版本管理尚未定义，因此界面只展示当前报告。

## Goals / Non-Goals

**Goals:**

- 在 `800px` Drawer 中清晰展示报告风险概览和结构化摘要。
- 支持带明确覆盖提示的重新生成当前报告。
- 在同一个 Drawer 内完成导出文件名、格式选择与导出。
- 支持从报告阶段推进至修复阶段，并以服务端 Workflow 状态为事实来源。

**Non-Goals:**

- 不实现首次生成报告、迁移输入选择、冲突处理或报告历史版本列表。
- 不增加问题明细表、修复执行、SSE 或轮询。
- 不提供报告正文在线编辑，也不在前端计算风险或工作量。

## Decisions

### 当前报告作为唯一展示模型

`GET /projects/:projectId/workflow/stages/report` 返回阶段状态、当前报告标识、三项风险指标和结构化摘要。前端仅负责展示，不根据迁移输入自行计算总体风险、高风险数量或预计工作量。

首次报告由迁移输入合并阶段生成；本 Drawer 在没有报告结果时展示空状态和返回 Workflow 的路径，而不是重复提供首次生成入口。重新生成使用当前报告标识调用 mutation，并明确覆盖当前结果。

替代方案是由报告 Drawer 重新读取迁移输入并自行生成。该方式会重复前一阶段的资格规则和领域逻辑，因此不采用。

### 紧凑的无表格报告布局

Drawer 使用 `800px` 宽度：标题下方放置总体风险、高风险问题和预计工作量三张摘要卡；主体使用结构化键值行呈现评估结论、主要风险、依赖替代性、建议路线和下一步动作；Footer 保留重新生成报告、导出报告和进入修复阶段。

报告不展示来源、冲突策略或迁移输入选择，以避免重复前置阶段的配置。摘要长文本在内容列自然换行，标签列保持稳定宽度。

### 导出使用 Drawer 内部视图

“导出报告”切换至同一个 Drawer 的导出视图，配置文件名与 `HTML`、`JSON`、`Markdown` 格式。格式变化时默认文件扩展名同步变化；用户手动修改文件名后仍需校验与格式相匹配的扩展名。

导出不改变报告或 Workflow 状态，因此不额外二次确认。导出 mutation/下载失败必须在当前视图提供恢复路径；成功后返回报告结果视图。

替代方案是在 Drawer 上叠加 Modal。现有阶段交互已统一使用 Drawer 内部视图，叠加 Modal 会增加焦点、关闭和尺寸管理复杂度，因此不采用。

### 重新生成与进入修复均需确认

重新生成会覆盖当前报告，使用 Popconfirm 明确提示影响；成功后失效报告详情和 Workflow 状态 query。进入修复阶段同样通过确认操作发起服务端阶段推进，成功后刷新 Workflow。

报告不维护本地“已生成”状态；按钮可用性完全取决于服务端返回的当前报告和阶段状态。

## Risks / Trade-offs

- [重新生成覆盖当前报告且没有历史列表] → 二次确认明确说明覆盖语义，后续版本管理另立 change。
- [摘要文本较长] → 使用 `800px` Drawer、固定标签列与内容换行，避免为了文本引入表格横向滚动。
- [导出文件名与格式不一致] → 格式切换同步默认扩展名，提交前执行客户端校验并展示字段错误。
- [报告不存在或生成失败] → 使用服务端阶段状态显示空数据或失败，并提供重新打开/重试路径而不伪造报告内容。

## Migration Plan

1. 新增评估报告领域类型、API、mock 和测试，读取迁移输入合并阶段首次生成的当前报告。
2. 新增 `StageDrawer/AssessmentReport`，实现报告结果与导出内部视图。
3. 在 `StageDrawer/index.tsx` 注册 `report`，接入重新生成、导出和进入修复后的 query 刷新。
4. 增加交互测试，并记录仍待确认的原型差异到根目录 `problem.md`。

回滚时移除 `report` 专属 Drawer、领域 API 与 mock；固定 Workflow 节点继续使用默认 Drawer。

## Open Questions

- 导出成功后后端返回一次性下载 URL、文件流还是异步文件任务；前端 API 将以正式接口契约为准。
- 报告重新生成后是否需要保留可追溯版本；当前明确只覆盖当前报告，后续再定义版本列表与对比能力。
