## Why

后端新版迁移报告已经提供模块、文件、问题类型、Finding 与不可变源码上下文的分层查询能力，当前前端仍将所有报告输入拉取后平铺为优先处理队列，无法表达真实影响范围，也无法利用报告绑定的源码上下文定位问题。

## What Changes

- 新版报告以模块作为代码迁移的一级主体，展示模块风险、文件数量、Finding 数量及问题类型分布。
- 用户从模块进入文件列表，再从文件进入问题与联合源码上下文；问题类型只作为统计和筛选条件。
- 依赖输入作为按需展开的辅助区，不将依赖强行归入代码模块。
- 开发阶段统一采用新版模块视图，不保留旧报告的平铺兼容界面。
- 新增报告组织 API 类型、请求封装、查询缓存键和页面交互测试。

## Capabilities

### Modified Capabilities

- `project-pipeline-workbench`: 评估报告统一展示服务端组织的模块、文件及源码证据。

## Impact

影响评估报告 Drawer、项目报告领域类型、API 请求与查询缓存键，不修改后端接口或报告生成逻辑。
