## Context

新版报告以 `organizationAvailable` 标识模块组织能力，并提供“模块 -> 文件 -> 问题类型 -> Finding”的分页接口及文件联合源码上下文。后端层级描述数据关系，但前端若直接渲染为四层嵌套折叠，会造成过深导航和过长页面。

## Goals / Non-Goals

**Goals:**

- 建立“报告总览 -> 模块详情 -> 文件详情”的稳定阅读路径。
- 让问题类型承担统计与筛选职责，并在文件详情同步问题列表与源码高亮。
- 首屏只读取模块摘要，按用户进入的层级加载文件、Finding 和上下文。
- 保留依赖清单入口。

**Non-Goals:**

- 不在前端生成工作包、处理优先级、前置依赖或验收标准。
- 不兼容或推断旧报告的模块归属。
- 不修改后端报告组织与模块识别规则。

## Decisions

模块列表使用连续的全宽列表，以模块名称、最高风险、文件数、Finding 数和问题类型分布建立主层级。点击模块进入独立模块详情，避免嵌套展开所有文件。模块详情中的问题类型标签用于筛选文件，文件路径是列表主识别信息。

文件详情在同一 Drawer 内展示问题类型筛选、分页 Finding 列表和服务端返回的联合源码上下文。源码使用项目共享的 Monaco 编辑器单实例展示，保留接口提供的真实行号，并将行内列范围转换为 Monaco decoration；选择 Finding 时同步突出对应源码行。结构化省略区间按需请求对应行范围，再合并进同一个编辑器模型。无法读取上下文时保留问题列表并展示稳定原因。

代码模块直接作为报告主体展示，不设置模块、依赖和证据的平级页签。存在依赖输入时展示可展开的依赖清单辅助区，并只在展开后读取不可变输入接口。报告 ID 与内部结构版本不在业务界面展示。开发阶段统一进入模块化报告视图，旧报告数据可直接清理或重新生成。

## Risks / Trade-offs

- [模块或文件数量较大] -> 使用服务端分页、搜索与排序，避免一次加载完整层级。
- [问题类型筛选影响文件统计] -> 文件列表明确显示当前筛选结果，并允许一键恢复全部类型。
- [源码上下文不可用] -> 保留 Finding 列表，不把上下文失败升级为整个报告失败。
