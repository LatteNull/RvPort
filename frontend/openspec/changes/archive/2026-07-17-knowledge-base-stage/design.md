## Context

项目工作台已有固定维护的 `kb` Workflow 节点，但 `StageDrawer` 尚无知识库扫描实现。原型中的扫描配置和 Finding 详情以 Modal 呈现；当前阶段 Drawer 的交互约定要求复杂流程在同一个 Drawer 内切换视图，避免 Drawer 与 Modal 的叠加层级。

知识库扫描是服务端长任务：前端负责提交配置、读取任务状态和展示结果，扫描任务及 Finding 是服务端事实。当前不引入 SSE 或定时轮询。

## Goals / Non-Goals

**Goals:**

- 在 `kb` 节点点击后提供知识库扫描的结果、配置和 Finding 详情视图。
- 明确区分临时勾选与 Finding 是否已进入迁移问题清单的持久状态。
- 复用 BaseDrawer、TanStack Query、Ant Design 和已有 Monaco 集成，保持阶段 Drawer 交互一致。
- 为开发期提供与正式 API 包络一致的类型、领域 API、Vite mock 和测试。

**Non-Goals:**

- 不实现知识库扫描器、规则引擎、真实报告文件生成或迁移问题清单页。
- 不保存或浏览历史扫描版本，不引入 SSE、轮询或任务进度百分比。
- 不提供 Finding 忽略功能；结果状态仅为“未加入”和“已加入”。
- 不在本 change 中重构其他阶段的配置 Modal；仅确立本阶段的 Drawer 内视图模式。

## Decisions

### 以单个 Drawer 管理三个视图

知识库扫描组件维护 `results`、`config`、`detail` 三个本地视图：

```text
results --新建扫描--> config --开始扫描--> results（任务运行中）
results --规则 ID/文件--> detail --返回--> results
```

结果视图允许关闭 Drawer。配置与详情视图隐藏右上角关闭按钮并阻止遮罩/键盘关闭，以避免用户误离开当前子流程；配置取消或详情返回显式回到结果视图。配置表单和详情不使用 Modal。

替代方案是在 Drawer 上打开 Modal。该方案会产生双层浮层、重复 Footer 与关闭语义，且与环境管理阶段的 Drawer 内视图约定不一致，因此不采用。

### 按主内容确定 Drawer 宽度

Stage Drawer 按主视图复杂度取两档尺寸：含主结果表格的阶段使用 `1100px`，以信息或表单为主的阶段使用 `800px`。知识库扫描的结果、配置和详情作为同一阶段的内部视图，均保持 `1100px`，避免导航时宽度跳变。

结果 Table 保留横向滚动；“原因”和“建议”设置可读的最小列宽，不为了消除横向滚动而截断关键内容。

### 任务状态与数据请求边界

使用 TanStack Query 加载当前扫描任务摘要和该任务的 Finding 列表；使用 mutation 提交新扫描、加入迁移问题清单和导出报告。请求成功后精确更新或失效对应 query，并失效项目 Workflow 状态 query，以便 `kb` 节点展示服务端返回状态。

前端展示 `PENDING`、`RUNNING`、`SUCCEEDED` 和 `FAILED` 等服务端任务状态。当前 change 在提交和显式刷新后读取权威状态，不建立 SSE 或定时轮询；重新进入 Drawer 时必须重新使用当前任务状态。

### 结果选择与持久状态分离

`selectedRowKeys` 仅表示当前 Table 的临时勾选，用于全选、取消全选和批量加入。每条 Finding 的 `migrationStatus` 是服务端持久事实，只映射为“未加入”或“已加入”。

加入操作必须至少选择一条结果，并通过二次确认后提交；成功后刷新 Finding 状态，但不自动推进后续 `merge` 阶段。详情页可对当前单条 Finding 使用相同加入操作；已加入时按钮禁用并展示已加入状态。

### 扫描配置与结果布局

结果视图首屏只展示阻塞问题、迁移缺口和已兼容/已隔离三项概览，以及 Finding 结果区域。规则版本、扫描范围和排除项不以标签重复堆叠在结果页，而在“新建扫描”配置视图维护。

配置表单包含规则版本、扫描语言、扫描范围、宽松匹配的排除目录名和精确排除路径。排除规则说明紧邻对应字段；精确排除路径为按行填写的多行输入。扫描启动是全局任务操作，位于配置视图 Footer；新建扫描入口位于结果区标题右侧，导出报告位于结果视图 Footer。

### Finding 详情使用按需只读 Monaco

详情视图采用上方双栏和下方整行：左侧为代码上下文，右侧为规则来源，底部为风险原因、修改建议和后续动作。代码上下文沿用本地 Monaco worker 配置并以只读模式按详情视图打开时加载，避免结果列表初始渲染加载编辑器资源。

详情入口通过文件名或规则 ID 提供，不增加额外“操作”列，结果表固定为选择、文件、行号、规则 ID、风险、原因、建议、状态八列。

## Risks / Trade-offs

- [无轮询或 SSE 时运行中状态不会自动完成] → 提交 mutation 后刷新状态，并在用户重新打开 Drawer 时获取权威状态；后续实时任务 change 统一补充订阅策略。
- [八列表格在窄视口横向溢出] → Drawer 使用 `1100px`，Table 保留受控横向滚动并避免压缩原因和建议列。
- [再次扫描会替换当前可见结果] → 配置提交前明确提示新扫描将更新当前展示结果；仅在服务端任务成功后切换为新结果。
- [代码上下文体积较大] → Monaco 仅在详情视图动态加载；服务端返回有限上下文而非完整源码文件。

## Migration Plan

1. 增加知识库扫描领域类型、API、mock 与测试 fixture。
2. 新增 `StageDrawer/KnowledgeBase` 组件并注册 `kb` 节点映射。
3. 在现有阶段 Drawer 中落实两档宽度规则，确保已存在表格阶段与信息阶段的尺寸一致。
4. 验证 mock 的任务状态、结果选择、详情和错误/空态；若后端契约尚未就绪，以正式包络 mock 作为开发边界。

回滚时移除 `kb` 专属 Drawer 注册并保留既有 Default Drawer；新增 API 和 mock 不影响其他阶段请求。

## Open Questions

- 正式后端接口是否提供扫描任务完成后的主动事件；若提供，应由后续统一任务事件 change 接入，不在本阶段自建连接。
- 导出报告的正式产物类型、下载地址和异步状态尚未确定；首期以当前扫描结果的全局导出动作和 mock 成功反馈建模。
