## Context

RvPort 前端已切换到 Ant Design，并开始形成统一的布局和组件样式规则。当前认证后页面由 `MainLayout` 承载，页面内容通过各页面自己的 `.page` 样式控制宽度。这个方式会让全局布局规范散落在业务页面里，也会导致后续页面宽度不一致。

首页项目列表使用固定卡片宽度，适合对齐 Figma 中的大屏卡片墙，但在窗口变窄或打开浏览器 DevTools 时，固定列宽会让剩余空间集中在右侧，视觉上显得页面没有填满。

## Goals / Non-Goals

**Goals:**

- 将认证后页面的最大内容宽度和居中行为放到 `MainLayout`。
- 让 Header 和内容区使用一致的横向 padding。
- 减少中等宽度窗口下左右 padding 过厚的问题。
- 让首页项目卡片网格在保持最小卡片宽度的同时自动拉伸填满可用宽度。
- 为项目流水线工作台顶部摘要卡片建立清晰的标题、辅助文本、状态色和背景图层级。
- 保持改动轻量，不引入新的设计 token 层。

**Non-Goals:**

- 不重新设计 Home 页卡片内容结构。
- 不改变项目详情页、项目流水线工作台的业务交互。
- 不改变项目摘要数据、Workflow 状态或页面操作能力。
- 不新增依赖或切换样式方案。
- 不引入全局 `variables.scss` 或项目私有 CSS 变量体系。

## Decisions

### 全局内容宽度放在 `MainLayout`

认证后页面共享 Header、内容滚动区和路由出口，因此最大内容宽度应该放在 `MainLayout` 的内容内层容器，而不是由 Home 单独维护。

备选方案是在每个页面的 `.page` 中重复 `max-width` 和 `margin: 0 auto`。这个方案短期可用，但后续详情页、工作台页容易出现宽度不一致。

### 保留较大的最大宽度，但降低横向 padding

首页当前卡片最小宽度约为 `315px`，五列加四个 `20px` gap 需要约 `1655px`。全局容器保留 `1660px` 可以支持大屏五列展示；同时将主布局左右 padding 从 `60px` 降到更克制的值，改善中等宽度窗口下的有效空间。

### 首页网格使用 `minmax(315px, 1fr)`

项目卡片本身已经是 `width: 100%`，因此网格列可以从固定 `315px` 改为最小 `315px`、最大自动分配剩余空间。这样当容器只能放三列或四列时，每列会自然拉伸，避免右侧出现大块空白。

### 工作台摘要卡片使用 CSS 背景图

项目流水线工作台已有四张语义明确的摘要卡片，背景插画使用各卡片样式中的 `background-image` 引入，并固定在右下角。这样图片不参与布局、不遮挡文本，也不需要在 JSX 中增加无语义的图片节点。

标题统一使用 `16px/20px`、`500` 字重和黑色；辅助文本使用 `12px/20px` 与 `#666666`。风险等级与问题数量使用 `#FF3737`，当前阶段使用 Ant Design 主题主色，以保留主题配置的统一入口。

## Risks / Trade-offs

- [Risk] 卡片在三列布局下会比 Figma 固定卡片略宽。→ Mitigation: 保持 `315px` 最小宽度，卡片内部文本继续使用省略和自适应布局。
- [Risk] 全局 `contentInner` 会影响所有认证后页面。→ Mitigation: 保持容器只控制宽度、居中和高度，不侵入页面内部布局。
- [Risk] 某些未来页面需要全宽工作区。→ Mitigation: 后续可在布局层增加显式的全宽路由模式，而不是让普通页面默认全宽。
