## Context

固定 Workflow 已有 `merge` 节点，但尚无专属 Drawer。知识库扫描、知识库 AI 扩展、SBOM 以及后续专项分析会形成不同来源的迁移问题；这些结果可能重复或给出相互矛盾的建议，不能未经处理直接作为评估报告输入。

本 change 只负责形成可确认的迁移输入基线。`assessment-report-stage` 负责消费该基线并展示、导出评估报告。

## Goals / Non-Goals

**Goals:**

- 在同一个 Drawer 内完成输入来源配置、结果审阅、冲突处理与问题确认。
- 以服务端合并结果、冲突状态和确认状态为事实来源，表格使用 BaseTable 服务端分页。
- 确保报告只能基于至少一个已确认问题且不存在待处理冲突的合并结果生成。
- 让输入来源配置视觉上位于列表筛选栏，但保持其“重新合并数据”的业务语义。

**Non-Goals:**

- 不实现上游扫描、AI 建议、SBOM 或专项分析的业务逻辑。
- 不实现评估报告详情、重新生成或导出；这些属于 `assessment-report-stage`。
- 不支持忽略冲突、将冲突带入报告或在表格中本地合并数据。
- 不引入 SSE、轮询、历史合并版本或跨 Drawer 共享未提交的行选择。

## Decisions

### 阶段详情、合并集与分页结果分层

`GET /projects/:projectId/workflow/stages/merge` 返回阶段状态、概览计数、当前合并集标识和报告生成资格。`GET /migration-input-merges/:mergeId/items` 使用 `page`、`pageSize`、关键词、来源、风险、冲突与状态筛选返回服务端分页结果。

输入来源提交、冲突处理和问题确认均通过 mutation 更新服务端合并集；成功后失效阶段详情、列表和 workflow 状态 query。前端不得在当前页数组上自行去重、推导冲突或修改确认状态。

替代方案是在前端把各来源结果拉齐后合并。该方案无法保证分页、确认和报告基线的一致性，且会把领域规则放入展示层，因此不采用。

### 来源配置位于筛选栏，但不是展示筛选

结果视图的筛选栏左侧包含 `输入来源`、风险、冲突、状态和关键词。`输入来源`打开 Drawer 内部的来源配置视图，列出当前可用的上游来源及其候选数量，并提供冲突策略选择。

提交“重新合并”会重算当前合并集，再返回结果视图；它不同于风险、冲突、状态和关键词筛选，后者只改变列表查询条件。这样保留用户期望的表头筛选式入口，同时避免误导为本地过滤。

### 冲突必须先处理，不能随确认或报告绕过

冲突行的操作列提供“处理冲突”，在同一个 Drawer 内进入冲突处理视图。该视图展示各来源结论，允许选择一个来源结论或填写手工合并结论；确认后该行不再处于待处理冲突状态。

表格选择工具栏仅在所选行均无待处理冲突时启用“确认已选问题”。只要整个合并集中仍存在待处理冲突，Drawer Footer 的“生成评估报告”即保持禁用并说明数量。该规则避免不确定的迁移建议进入后续评估。

替代方案是让用户带冲突确认并在报告中标记。该方案会让报告的输入边界不明确，与“确认”作为评估依据的语义冲突，因此不采用。

### 选择、确认和报告生成是三个独立状态

表格 checkbox 仅表示当前用户选择的候选项；`确认已选问题`将无冲突选项写入已确认基线；`生成评估报告`仅在基线有效时发起 Workflow 推进。选择状态是 BaseTable 局部状态，确认状态由服务端结果字段返回，报告资格由阶段详情返回。

生成报告操作通过统一阶段推进/报告创建 API 发起，并在成功后刷新 workflow 状态。报告内容和导出由后续 change 接管，当前 change 只保证交接前置条件和触发契约。

### Drawer 结构与宽度

结果视图固定为 `1100px`，包含三项紧凑摘要、筛选栏、BaseTable 和 Footer。表格使用 `small` 尺寸和 BaseTable 的内容优先自动高度；选择工具栏位于分页栏左侧，分页位于右侧。

来源配置与冲突处理是同一阶段的内部视图，不在 Drawer 上叠加 Modal。两者隐藏常规关闭入口，只能通过取消、提交或返回回到结果视图；保持 `1100px` 以避免切换抖动。

## Risks / Trade-offs

- [上游阶段未产生结果] → 来源配置仅展示服务端返回的可用来源；无可用来源时说明无法合并并禁用提交。
- [长问题和建议文本挤压列宽] → 结果表使用受控列宽和横向滚动，Drawer 保持 `1100px`。
- [重新合并改变用户当前选择] → 成功重算后清空前端临时选择，要求用户重新审阅并确认。
- [报告生成 API 在报告阶段完成前尚未接入] → 将 API 契约和资格状态写入本 change；后续 report change 负责报告详情消费与导出。

## Migration Plan

1. 增加迁移输入合并领域类型、API 契约、mock 和 API 测试。
2. 新增 `StageDrawer/MigrationInputMerge`，实现结果、来源配置与冲突处理内部视图。
3. 在 `StageDrawer/index.tsx` 注册 `merge`，并在 mutation 后刷新 workflow 状态。
4. 由 `assessment-report-stage` 基于已确认迁移输入与报告生成结果接续报告 Drawer。

回滚时移除 `merge` 专属 Drawer、领域 API 与 mock；Workflow 节点仍由默认 Drawer 兜底展示。

## Open Questions

- 冲突处理的手工合并结论是否需要结构化字段，还是先以单段文本保存；本 change 先要求服务端返回可展示的最终建议。
- 评估报告创建成功后是否保留报告版本历史；该策略由 `assessment-report-stage` 单独决定。
