## Why

构建验证节点已在前端拓扑中定义，但当前被延后隐藏，也没有专属 Drawer，因此用户无法基于已部署的当前源码在 x86 与 RISC-V 项目级环境中发起和追踪构建。现有后端已提供构建、列表、详情和取消接口，应将这条能力接入当前工作流。

## What Changes

- 放开“构建验证”节点，使其在项目流水线画布中可见、可点击，并提供专属 Stage Drawer。
- 在 Drawer 中展示当前源码、项目级源/目标环境以及当前源码在两侧环境的部署前置状态。
- 将构建前置准备拆分到源/目标环境各自的卡片：每侧独立完成基础环境检查与源码工作目录配置/校验，并支持单侧重试。
- 在两侧目录均校验成功后，通过构建阶段的项目级“准备当前源码”动作，按项目运行环境配置同时准备两个环境的当前源码；请求不得指定环境。
- Drawer Footer 仅提供“开始构建”；仅在两侧均已完成源码环境准备并具有当前源码的成功部署记录时启用。
- 基于既有构建接口，以一份公共构建脚本、超时和环境变量同时创建两个环境的构建任务。
- 提供构建记录列表、详情日志与运行中任务取消操作。
- 不新增构建配置持久化、环境专属构建命令、独立构建工作目录、单环境源码部署或构建批次模型。

## Capabilities

### New Capabilities

- `build-validation`: 基于当前源码部署和项目级运行环境执行、查看与取消双环境构建验证。

### Modified Capabilities

- `project-pipeline-workbench`: 将构建验证纳入当前可见、可操作的项目流水线工作台。

## Impact

- 影响 `src/pages/project-detail/Workflow/`、`src/pages/project-detail/StageDrawer/`、项目领域 API 与类型。
- 复用现有项目运行环境、源码部署、环境检查、构建验证和任务日志 API；不引入依赖或修改后端接口。
