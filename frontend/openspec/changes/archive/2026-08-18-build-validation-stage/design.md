## Context

构建验证后端已支持读取当前有效源码、项目级运行环境与双侧成功源码部署，并以一份公共脚本创建两个独立构建任务。前端拓扑中已定义 `build` 节点，但该节点处于 deferred 集合，且 StageDrawer 没有对应实现。

现有接口不支持持久化构建 Profile、环境专属命令、用户指定源码部署记录或构建批次。环境检查接口可对指定工作目录异步执行连接、基础工具、目录与权限检查。

## Goals / Non-Goals

**Goals:**

- 将构建验证作为当前工作流中可点击的阶段接入。
- 在同一 Drawer 内完成每侧独立的前置准备、公共脚本填写、构建发起与记录查看。
- 以服务端任务与构建记录为事实来源，处理加载、失败、取消和重新进入 Drawer 的状态恢复。

**Non-Goals:**

- 不修改后端 API 或数据模型。
- 不新增构建配置保存、不同环境的工作目录/构建命令、构建批次聚合或源码对比能力。
- 不纳入自动化测试、Benchmark、Profiling 等后续阶段。

## Decisions

### 使用同一 Drawer 的状态视图

构建概览、构建前检查、构建记录详情和日志均属于同一阶段，采用与现有 StageDrawer 一致的同 Drawer 二级视图切换，而不是 Drawer 内打开 Modal 或第二个 Drawer。点击构建记录的“日志”后进入独立详情视图；返回入口使用与 SBOM 二级视图一致的 Drawer 标题栏左侧圆形返回图标，并在二级视图中禁用直接关闭。日志内容采用条目模式：每条事件显示类型与元信息，摘要放入不依赖编辑器的原生只读日志块；日志块按内容自适应，较长内容在上限内显示并独立滚动。日志列表保留分页，避免表格或整段文本随事件数无限撑高。构建主视图宽度为 1100px，以容纳双环境摘要和构建记录表。

### 两侧环境独立完成构建前置准备

源环境与目标环境是独立资源，Drawer SHALL 在两张环境卡片中分别提供操作和状态：基础环境检查（连接与基础工具）、源码工作目录编辑、以及源码目录与权限校验。任何一侧失败时，用户只需在该侧卡片修复并重试，不应重复操作另一侧。

环境管理的 `workingDirectory` 是源码部署根目录；源码部署为当前源码版本在该根目录下生成 `remotePath`，后端构建在该 `remotePath` 中执行脚本。目录校验针对用户配置的源码工作目录；构建记录和最终执行目录仍以服务端返回的成功部署 `remotePath` 为事实来源。

### 项目级准备当前源码，Footer 仅承担构建提交

两侧目录均校验成功后，Drawer SHALL 在构建前置区域提供项目级“准备当前源码”动作。该动作调用既有源码部署接口时只提供当前源码版本；后端根据项目运行环境配置同时处理源/目标两个环境，前端不得指定环境 ID，也不得将它表示为任一环境卡片的单侧部署按钮。

源码准备完成后才展示构建脚本、超时和环境变量配置。“开始构建”位于构建配置区的右下角，不使用 Drawer Footer。只有源/目标两侧均存在当前源码的成功部署记录时，才启用该操作。实际构建仍由后端重新校验项目级环境、当前源码和对应配置版本下的成功部署记录。

成功部署记录可在重新打开 Drawer 时复用；源码版本、运行环境或源码工作目录变化，或者服务端不再返回成功部署记录时，对应一侧重新进入未部署状态。基础检查和目录校验按环境独立发起与重试；其展示结果不应让一侧阻塞另一侧的操作。

“构建前置条件”和“构建配置”区块默认展开且支持独立收起；环境卡片不单独提供收起操作。卡片中的“基础环境”“目录与权限”和“当前源码”均采用左侧标签、右侧状态与操作/路径的单行布局；部署路径在可用空间不足时截断，不得挤压标签换行。

### 采用公共构建脚本

构建配置只暴露现有 `BuildValidationCreateRequest` 支持的 `script`、`timeoutSeconds` 与 `environmentVariables`。后端将该脚本在两个已部署环境中分别执行并返回两条构建记录。不能在 UI 中宣称支持环境专属命令。

### 画布节点保持可访问，执行受前置条件控制

`build` 从 deferred 集合移除并注册专属 Drawer。节点点击始终可用；Drawer 根据数据展示缺失环境、缺失源码或缺失部署，并提供跳转或部署动作，而不是通过不可点击节点隐藏问题。构建节点的静态默认状态为 `pending`，服务端 workflow 快照存在对应状态时优先使用服务端状态。

## Risks / Trade-offs

- [环境检查任务与构建没有后端强关联] → 前端将检查视为每侧准备状态，并在发起构建失败时刷新前置数据并展示服务端错误。
- [没有持久化脚本] → 明确将脚本视为当前 Drawer 会话输入，不展示“已保存配置”或虚假的历史配置。
- [双构建记录没有批次 ID] → 列表按独立环境记录展示；不提供跨刷新的一次构建批次聚合。
- [部署记录变化导致检查结果过期] → 在当前 Drawer 会话中源码、运行环境配置或部署状态刷新后清除本地检查成功状态。

## Migration Plan

1. 新增前端 API 类型与 StageDrawer，不改变服务端接口。
2. 从 deferred 集合放开 `build`，并调整与当前可见流程相符的画布边。
3. 通过现有 mock 或接口 fixture 覆盖前置缺失、检查失败、构建中与完成状态。
4. 出现问题时可重新将节点加入 deferred 集合并移除 Drawer 映射；不涉及数据迁移。
