## 背景与目标

后端提交 `555edea` 已按独立循环与归约候选输出 schema v2 Finding。前端当前列表使用 `rowKey=id`，点击详情也以 Finding ID 请求和重建工作区，未发现规则/文件/编译单元二次合并。

## 设计决定

- 保留 API 返回条目与分页总数，不新增合并或按 occurrence 数量拆分逻辑。
- 列表补充结论状态，详情的主位置、证据、置信度和状态始终来自所选 Finding。
- 单位置不显示位置选择器；多位置按 primaryOccurrenceId 选择初始位置，切换仅作用于同一 Finding。
- 使用真实列表与详情组件、mock API 边界，验证同函数两个循环产生的两个 Finding 独立保留；另覆盖历史单 Finding 多 occurrences。此测试是前端消费合同验证，不宣称已实际重跑分析器。

## 限制

用户明确不需要部署，随后取消本轮检查、测试和构建执行。因此未重新扫描真实项目，也未执行新增测试。主规范不提前同步，变更保持未验收。
