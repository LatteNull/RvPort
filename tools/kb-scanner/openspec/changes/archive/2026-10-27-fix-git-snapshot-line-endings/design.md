## Context

Git 中 Clang 数据为 LF，SHA-256 为 `947e2ad0797248f8179f2bc29f4e7e0591bd7a14801ba819c9e56d31926e9a8c`；Windows 的 `core.autocrlf=true` 工作区混合换行为旧摘要。GCC 当前工作区与 Git 都是 LF。Docker 隔离了运行环境，却不会自动规范 COPY 输入的换行；默认 Windows `git archive` 也可能进行换行转换。此前只核对 57 个变更文件，没有验证未修改的知识和夹具输入。

## Goals / Non-Goals

**Goals:**
- 明确 KB Scanner 文本的 LF 合同，以 Git blob 为来源维护原始字节基线。
- 保留所有事实类别、generatedSet 引用、扫描结论和现有输出结构。
- 使当前提交候选的干净 Linux 快照通过完整单测、覆盖率与回归，并将检查经验写入提交技能。

**Non-Goals:**
- 不改变检测、解析、就绪状态或操作系统迁移逻辑；不把缺少证据解释为就绪。
- 不重建编译器知识、不抹去历史账本、不降低覆盖率、不设置用户全局 Git 配置。
- 本次更新技能不自动执行 commit/push，不整体规范其他子项目。

## Decisions

1. 在 KB Scanner 根增加 `* text=auto eol=lf`，由 Git 识别文本，已有更深层属性继续生效。对当前受影响的已跟踪文本只进行 CRLF→LF，证明与 Git blob 一致；有意的 CRLF/二进制夹具须单独保留。拒绝单纯更新数字以适配各机器工作区。
2. 原始字节仍参与完整性检查，不在读取时静默归一化或改为只比较 JSON。更新当前 Clang 的长度、哈希及 manifest；活动消费者保持同步，历史归档、历史报告样例和差异账本仍保存旧来源。若报告摘要受来源哈希、源文件换行影响，逐字段审校差异，只更新当前基线，并保留前版证据。
3. 将必要的字节/事实合同验证提取到小型测试支持模块，提供明确的路径、长度、哈希和换行错误。隔离单测使用临时文件，覆盖 LF 成功、CRLF 污染、相同长度内容变更、计数/来源/manifest 不匹配、文件缺失及空内容等路径。该模块加入 runner 独立行/分支 90% 门槛；不新增业务模块。
4. 使用独立临时 Git index 从 HEAD 加入本次拟提交文件并生成 tree，不改变真实暂存区或创建提交。在 Docker 中解包受控导出的 tree，逐文件核对原始 Git blob 摘要，生成干净构建上下文；记录 HEAD/tree/镜像/报告。不能只用工作区 SHA 或默认 archive 自证一致。测试镜像从该快照构建，执行 18 个专项与完整回归；覆盖全部未加载自有源码及受影响模块，双 90% 不变。
5. 提交技能新增有条件的换行审计：涉及原始哈希、字节长度、文本夹具或 Windows→Linux Docker 输入时，检查 attributes、index、工作区及未修改依赖；内容变化先验证快照。发现不一致应按原有故障规则停止，不能在提交阶段擅自规范换行或更新基线。纯文档更新只做内容、链接和技能格式验证。

## Risks / Trade-offs

- 新增属性不自动改写已有工作区 → 针对受影响文本安全转换并审校，不执行覆盖用户修改的 checkout/reset。
- 改 manifest 可能改变知识来源身份和报告摘要 → 分类计数、事实 JSON 值、结论和证据结构分别比较，保留旧基线作为追溯证据。
- 冻结夹具可能有有意的字节差异 → 先审计文件类型与属性，必要时保留更具体规则，不扩大到全仓库。
- 完整 Compose 构建依赖网络 → 顺序构建并复用依赖层，仍从当前快照复制源码；使用隔离项目、卷和端口并清理。

## Migration Plan

先核对 blob 和当前基线，再补属性与合同测试，更新活动摘要和技能；通过定向和完整快照测试后进行根 Compose 验收。全部通过才更新任务与验收记录；回退应回退属性、当前摘要和合同整组修改，不单独保留不匹配 manifest。
