## Why

现有测试分析能识别测试目标与文件选择，但仍可能把同一文件中的任意 x86 fact 当成测试正在验证的内容，缺少测试入口、局部调用、断言与架构条件之间的证明。宏与构建作用证明已经落地，现在需要把原始项目测试用例的内容纳入静态证据链，区分真实架构依赖、已隔离的 x86 测试与证据不足，避免仅凭测试目录或文件共现得出阻断结论。

## What Changes

- 增加原始 C/C++ 测试内容的有界清单：入口、函数体、直接调用、断言位置及其与既有 x86 fact 的关系。首版确认普通测试可执行程序的 main、唯一可解析的同 TU 一跳辅助函数，以及标准 assert 的受支持形式；第三方测试框架宏和动态注册只保留候选，不声称完整理解框架。
- 补齐 CMake 显式测试注册的静态恢复，连接 enable_testing、add_test、测试可执行目标、源文件及架构选择；复用已有机器元数据、Make/RPM 证据，不执行构建或测试。
- 分开表达“文件被编译”“测试被注册/选择”“内容属于测试入口或断言”三件事，禁止用文件共现代替测试内容证明。未调用函数中的 intrinsic 仍保留普通源码风险，不凭空证明测试执行。
- 分析既有架构事实在断言、局部条件及有限局部值绑定中的用途；原始 fact 不删除。不完整、动态、歧义或超预算路径保持 unknown，不把任意数值期望当成 x86 专属行为，不自动宣称通用/RISC-V 替代测试等价。
- 保持默认 V2、显式 V1 及 scan-result.json / scan-report.html / scan.log 合同；通过现有 evidenceChain 与命名空间 extension 展示测试语境，源码上下文仍为命中上下各 20 行，中文建议和 suggestion_en 同步维护。
- 同步增加全部受影响模块的隔离单元测试、包含未加载自有源码的整体及模块行/分支覆盖率至少 90% 门禁、误判反例、人工审校和容器性能验收。

## Capabilities

### New Capabilities

- `kb-scanner-test-content-analysis`：测试内容清单、入口/调用/断言的有界证明、事实用途与未知边界，以及质量验收。

### Modified Capabilities

- `kb-scanner-cmake-source-analysis`：显式测试注册、禁用属性与本地可执行目标的可定位静态关联。
- `kb-scanner-classification-and-assessment`：测试结论必须区分构建选择与内容证明，禁止文件共现、名称或缺失证明直接升级为测试阻断或覆盖缺口。
- `kb-scanner-report-schema-v2`：在既有 Finding 合同内自包含展示测试内容来源与断点，保持 V1/V2 兼容及双语展示。

## Impact

- 范围仅为 tools/kb-scanner：C/C++ 前端清单、CMake 静态适配、事实规范化、测试图分析/检测、分类、投影与对应文档和测试；不修改后端、其他工具或生产容器。
- 不增加原生解析依赖，复用现有 Tree-sitter、可选 Clang 和构建解析设施；不执行被扫描项目的代码、预处理器、CMake、Make 或测试发现脚本。
- 两份 generated/clang-x86-entries.json 与 generated/gcc-x86-entries.json 原样保留，继续消费现有编译器知识，不重启 legacy 分析、不引入旧 YAML 规则。
- 仅关注 C/C++ 的 x86→RISC-V 静态迁移，不涉及操作系统迁移、真实测试成功与交叉编译探测误选。有符号移位继续排在后续低优先级工作。
- 使用独立 kb-scanner-test 容器运行测试与覆盖率；不向本机安装依赖。所有新增和修改业务模块必须建立隔离单元测试映射，集成回归不能替代覆盖验收。
