## Context

`tests/run_container_tests.py` 通过独立进程执行多个领域门槛。部分入口仅扫描固定目录，部分只读取主测试，部分支持辅助测试但未按测试 ID 去重。知识检测复现为 76 个测试通过但归一化模块 88.31% 行覆盖；全量 855 个测试则为 95.45%。这属于测试映射漂移，而非扫描业务行为变化。

## Goals / Non-Goals

目标：使每个采用模块清单的子集可靠执行主测试及辅助测试，失败可定位；受影响子集及测试驱动逻辑达到行/分支均至少 90%；本地与 CI 使用同一个完整入口。

非目标：更改分析算法、扫描产物合同或知识数据，增加平台 CI 配置，恢复退役的真实环境测试。Clang/GCC 数据及 evidence/unknown 语义保持不变；没有新业务字段需要投影。

## Decisions

1. 在测试支持模块中实现共享映射加载器。保留现有领域目录 discover，以免丢掉未被清单列出的现有测试；额外加载清单全部 `unit` / `supportingUnits`，按稳定测试 ID 去重并排序。只接受项目 `tests/unit` 内真实 Python 测试文件，缺失、越界、导入错误及空测试模块直接失败。映射顺序不影响执行结果。不同清单结构保留适配，不强迫将所有门槛改为全量 discover。
2. 辅助映射依据被测行为维护，例如函数/用途归一化、候选覆盖和宏效果。不把真实 parser、外部进程或端到端验证当作新增隔离单元测试；需要时为实际边界使用 fake/mock。保留既有组件回归，单独报告。
3. 子集使用独立 coverage 数据文件，重新开始统计；辅助测试须在 coverage 启动后加载。所有纳入该子集的模块仍须被统计，即使没有被测试导入。受影响清单采用至少 90% 行与 90% 分支，保留更高阈值。
4. 共享加载器与编排逻辑另设隔离单元测试：临时目录/伪 loader 覆盖输入校验，真实小型测试模块验证选择、去重和失败传播；用 fake subprocess / coverage 验证编排，不在单元测试中递归启动完整门槛。测试驱动逻辑覆盖率单独检查，不混入业务源码分母。
5. Dockerfile.test 默认命令仍是完整入口，完整源码门槛继续覆盖 `kb_scanner`、`scripts`、`tools`。逐个修复完整入口暴露的映射漂移，然后再执行一次完整默认入口。开发文档标明局部命令不能代表完整验收，所有结果导出报告。
6. 干净镜像发现根 `.dockerignore` 的 `tools/**/build-*` 同时排除了 `build-selection-test-inventory.json`、`tests/fixtures/build-selection` 和构建支持文档。仅对这些 KB Scanner 已跟踪输入添加精确例外，保留真实构建缓存排除。通过重新构建和镜像内文件哈希校验验证，不依赖 `docker cp` 补源码完成最终验收。
7. 用户追加授权扩展离线回归修复，并明确移除已退役 AVX 夹具。删除专用外部 AVX 回归，混合测试保留本地用例；通用 V1/V2 投影和测量改用已跟踪的源码链样例。历史 schema 示例继续作为自包含 reader 合同，不再访问旧运行目录。核对当前编译器事实与知识 manifest、已有事实合同、六类计数和来源元数据一致后，为开源快照建立独立基线；保留旧账本，记录旧/新摘要与不能重建的历史限制。扫描业务代码与知识事实文件不变。

## Risks / Trade-offs

- 共享代码可能改变测试数量 → 以测试 ID 去重；测试证明主测试和辅助测试都实际执行，保留旧目录 discover。
- 老子集还可能有其他覆盖率缺口 → 逐项审计映射并补齐局部测试；无关业务重构不纳入本 change，验证未过不得归档。
- 提高分支门槛暴露既有不足 → 保持 90% 要求，不排除难测代码；如规模超出测试基础设施及相关测试维护，报告范围。
- Docker 源码缓存混淆结果 → 重新构建当前测试镜像，最终在独立、禁网、限额容器执行；临时诊断可只读挂载当前源码，但不把旧报告作为验收。

## Migration Plan

提案校验后实施映射加载与测试；完成隔离单元、全量及完整入口验证；同步主规范并校验；全部任务完成后归档。无需数据库或产物迁移，回退限于本 change 的测试基础设施和文档。
