# KB Scanner 跨平台源码基线规范

## Purpose

规定 LF 原始字节、可追溯基线、测试支持逻辑及提交前快照核对要求，确保 Windows 工作区与 Linux 验收使用一致的 Git 输入，并保留完整性检测。

## Requirements

### Requirement: 受控文本输入必须使用稳定的 LF 字节
KB Scanner 自有文本输入 MUST 通过 Git 属性声明 LF，保留有明确用途的二进制和特殊夹具属性。当前编译器事实基线 MUST 基于 Git 中的 LF 原始字节，不以平台工作区转换后的字节作为来源。

#### Scenario: Windows 和 Linux 检出
- **WHEN** 两个平台检出相同版本的受控事实文件
- **THEN** 文件 SHALL 具有一致的原始字节、长度和 SHA-256，JSON 数据、类别及来源元数据保持不变

#### Scenario: 工作区被写入 CRLF
- **WHEN** 冻结事实文件混入 CRLF 而 manifest 仍声明 LF 内容
- **THEN** 合同 SHALL 明确失败并指出文件路径，不静默归一化后声称原始字节一致

### Requirement: 当前基线更新必须可追溯且保留完整性检测
当前事实和报告摘要 SHALL 同步核对长度、SHA-256、类别计数、来源及 manifest。换行修复 MUST 保留历史账本和历史样例；当前摘要变化 SHALL 记录可证明的字节差异和独立语义检查，不删除断言以接受不明差异。

#### Scenario: 等长内容被篡改
- **WHEN** 文件长度不变但内容与冻结哈希不同
- **THEN** 合同 SHALL 失败，不能只凭字节数或解析成功判定完整

#### Scenario: 元数据与内容不匹配
- **WHEN** manifest、分类计数或来源与已核对数据不一致
- **THEN** 合同 SHALL 失败并保留可定位的诊断

### Requirement: 测试支持逻辑与提交技能必须防止工作区验证误判
新增测试支持逻辑 MUST 具有正常、边界和错误单元测试并达到行/分支至少 90%，全部自有源码和受影响模块也 MUST 达到双 90%。提交技能 SHALL 在原始字节敏感变更中检查 Git 与工作区输入一致性，覆盖未修改依赖；检测到不一致时遵循既有停止规则，不能自动更改换行、基线或远程历史。

#### Scenario: Docker 复制了 Windows 工作区
- **WHEN** 工作区容器通过但受控输入与候选 Git tree 的字节不同
- **THEN** 提交流程 SHALL 拒绝将该结果作为候选快照验收通过的证据

#### Scenario: 仅更新技能文档
- **WHEN** 只修改提交技能说明，没有用户授权执行新的提交与推送
- **THEN** SHALL 仅完成技能内容和格式验证，不因此创建提交或推送
