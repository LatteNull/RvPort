# 测试与覆盖率范围

[English](testing-and-coverage.md) | 简体中文

所有测试、依赖安装、编译与代码生成在 Docker 中执行。本文件区分统计范围与验收状态，不将尚未运行的检查记为通过。

KB Scanner 于 2026-10-21 在 Docker 中完成最新全量单元复验：855 个测试通过，190 个自有 Python 文件纳入统计，包括未加载源码。整体行覆盖率为 98.772%、分支覆盖率为 96.211%。本轮校正当前知识清单的摘要链，并补充无效清单、引用缺失或摘要不符、知识源身份与语义校验、符号链接越界测试；相关加载模块 `knowledge/provider.py` 行、分支均为 100%。这些数字仅对应该次 KB 单元测试，不代表其他模块或后续修改已重新验收。

## 排除项与独立验证

- jOOQ 生成类型由数据库 schema 和生成器产生，不计入自有 Java 业务逻辑分母；空库初始化、重复迁移、完整代码生成与编译单列验证。
- 单元测试代码、测试运行器和纯输入夹具不计入生产源码分母。被业务代码调用的自有质量门槛、工具及辅助脚本仍纳入相应模块统计。
- Python `Protocol` 的无实现声明和 `TYPE_CHECKING` 静态导入不包含运行时业务逻辑；不以排除异常路径提高数字。KB metadata 原有运行时校验排除已撤销。
- LLVM、GoogleTest、npm/Python/Java 依赖以及 MinIO 上游源码属于第三方实现，不计入自有代码分母；依赖仍须通过镜像构建和运行验收。
- 内存序工具只对已记录摘要、没有可执行内容的声明头作排除；内容变化时由质量入口重新判定。早期 Clang 18 实验采集器已移出交付目录，不再作为当前可执行代码保留。
- Dockerfile、Compose、SQL、构建描述和 Nginx 配置通过配置解析、实际构建、空库迁移与完整启动验证，不能用这些结果代替语言单元测试。
- 两个只用于早期 SSH 联调的镜像目录及 shell 入口已移出导入基线。KB 性能容器的 PowerShell 启动器属于测试运行器，有离线命令契约检查，不计入生产源码分母；没有 PowerShell 行/分支覆盖率报告，不声称该启动器达标。

## 报告与合计

本地 `.migration-reports/` 保存 JaCoCo XML、coverage.py JSON、llvm-cov JSON、内存序综合报告和测试日志。该目录、真实配置、镜像产物和临时验收脚本不进入新仓库。

跨语言结果应累加各报告的 covered/total 后计算，不能平均百分比；同时保留各语言和受影响模块的独立门槛。尚未验收的范围不能被遗漏后宣称整个仓库已达标。正式 API 运行验证、文档检查、OpenSpec 校验和完整 Compose 启动分别记录，不算作补齐单元覆盖率。
