# RvPort 安装指南

[English](installation.md) | 简体中文

## 环境与执行位置

宿主机准备 Docker Engine 或 Docker Desktop，并启用 Linux containers、BuildKit 和 Docker Compose。完整后端镜像需要 x86_64 Linux 构建环境，首次构建会下载 JDK、Node.js、Python、Clang/LLVM 和扫描器依赖。编译与测试均在容器内进行。

以下命令均在本项目根目录执行。PowerShell 示例使用当前目录解析路径，不依赖某台机器上的固定目录。

## 准备配置

```powershell
Copy-Item .env.example .env
```

编辑 `.env`，替换 PostgreSQL、RabbitMQ、Redis 和 MinIO 的密码，并保持后端对应配置一致。`change_me` 等内容是模板占位符。不要提交 `.env`。

使用容器生成 32 字节主密钥，将输出填入 `RVPORT_CREDENTIAL_MASTER_KEY`：

```powershell
docker run --rm python:3.12-slim python -c "import base64,secrets; print(base64.b64encode(secrets.token_bytes(32)).decode())"
```

该密钥用于保存的凭据加密；运行期间更换密钥需要单独处理已有加密数据。`RVPORT_CREDENTIAL_KEY_ID` 用于标识密钥版本，不是密钥本身。

| 配置 | 用途 |
|---|---|
| `COMPOSE_PROJECT_NAME` | 隔离 Compose 网络和卷，默认 `rvport` |
| `POSTGRES_*`、`REDIS_*`、`RABBITMQ_*` | 数据库、会话缓存和消息队列 |
| `MINIO_*`、`RVPORT_OBJECT_STORAGE_*` | 对象存储及分析制品 |
| `RVPORT_BACKEND_PORT`、`FRONTEND_PORT` | API 与 Web 界面对宿主机暴露的端口 |
| `RVPORT_CREDENTIAL_MASTER_KEY` | 自行生成的凭据加密主密钥 |
| `RVPORT_SPECIALIZED_ANALYSIS_*` | 专项分析开关和资源上限 |
| `RVPORT_FLOATING_POINT_*`、`RVPORT_MEMORY_ORDER_*` | 镜像中的扫描器及 worker 路径 |

默认端口为 API 8080、PostgreSQL 5432、Redis 6379、RabbitMQ 5672/15672、MinIO 9000/9001。宿主机端口已占用时，在 `.env` 中更改对应端口。容器之间仍使用 Compose 服务名与容器内部端口。

## 构建与启动

先验证 Compose 配置，再完整构建前后端和对象存储镜像。MinIO 原官方镜像已不可用，改为固定官方源码在 Docker 内构建，来源、摘要与许可见 [对象存储构建说明](../infra/minio/README.zh-CN.md)：

```powershell
docker compose config --quiet
docker compose --parallel 1 build
docker compose up -d --wait --wait-timeout 300
docker compose ps
docker compose logs --tail 100 backend backend-worker
```

`backend` 和 `backend-worker` 使用同一镜像。API 节点启动时启用 Liquibase；首次空库由迁移脚本建立结构。worker 不承担 schema 初始化。数据库扩展脚本位于 `backend/infra/postgres/init/`，业务迁移位于 `backend/src/main/resources/db/changelog/`。

API 健康检查地址为 `http://localhost:8080/actuator/health`，实际端口以 `.env` 为准。专项工具健康与整体 API 健康是不同检查，某个扫描器不可用时不能据此认定其他功能全部不可用。

数据库现有初始化脚本包含开发管理员 `admin`，其初始密码为 `admin123`，并标记首次登录必须修改密码。这是公开开发默认值，不是部署凭据；正式发布前仍需审查初始化方式。不要将该默认账号状态直接用于对外部署。

前端已纳入源码，默认访问 `http://localhost:8081`。单独重建前端时执行：

```powershell
docker compose up -d --build frontend
```

前端开发与测试步骤见 [前端说明](../frontend/README.zh-CN.md)。模型、邮件、SSH 源环境和目标环境通过正式管理能力配置；不存在测试支持 API 初始化入口。

## 停止与数据

```powershell
docker compose stop
docker compose down
```

这些命令保留命名数据卷。`docker compose down -v` 会删除该项目数据卷，只有明确不再需要数据库和制品数据时才使用。迁移验收应使用独立项目名、端口和数据卷，不连接旧部署。

## 常见问题

- 工具链下载失败：检查容器访问软件源、GitHub release 和依赖仓库的网络条件，保留完整构建日志；不要改用旧镜像冒充重新构建成功。
- Node 或 npm 镜像超时、连接重置：可通过 `docker compose --parallel 1 build --build-arg NODEJS_MIRROR=https://nodejs.org/dist --build-arg NPM_REGISTRY=https://registry.npmjs.org` 使用官方源。保持依赖版本不变；更改构建参数可能使已有缓存层失效。
- 数据库结构不存在：确认 API 节点 Liquibase 已执行，检查数据库迁移日志和目标数据库名。
- 凭据无法保存或读取：检查主密钥是否为有效的 32 字节 Base64 值，以及是否错误更换了已有环境密钥。
- worker 没有执行任务：检查 RabbitMQ、worker 日志、数据库连接及 worker 注册状态。
- 源码或 bitcode 不完整：按照对应工具协议处理降级和缺失证据，不把空结果当作分析成功。
- 宿主机环境差异：使用 Docker 中的构建与测试入口，不在宿主机安装依赖来绕过错误。
