## Context

自动化测试节点位于构建验证之后。当前后端已经具备任务运行时、RabbitMQ worker、SSH runtime、任务日志文件、任务日志 SSE、`test_runs` 表和项目访问守卫，但自动化测试 API/handler 仍未落地。

本 change 的范围只覆盖远程测试运行后的输出和日志回收：

- 在指定远程环境执行用户提供的测试命令或脚本。
- 回收退出码、stdout、stderr、开始/结束时间、日志引用和测试生成的文字报告。
- 将状态通过任务事件和 SSE 暴露给前端。
- 不做 x86/RISC-V 对比，不做 Codex 日志比较，不解析 JUnit/CTest/pytest 等结构化报告。

## Goals / Non-Goals

**Goals:**

- 提供 `AUTOMATED_TEST` 任务类型和 handler。
- 补齐自动化测试 API：创建、列表、详情、取消。
- 将测试输出写入任务日志事件和完整日志文件元数据。
- 回收用户指定的测试报告文件或报告输出目录中的受控报告产物，并保存对象存储制品引用。
- 将测试运行摘要保存到 `test_runs`。
- 保持项目访问权限校验和敏感信息脱敏。
- 覆盖正常流程、异常流程和 edge case，并补充 E2E 模块用例。

**Non-Goals:**

- 不实现日志比较或 Codex 调用。
- 不实现双环境结果差异分析。
- 不解析测试框架结构化报告。
- 不创建 `test_cases` 或失败用例重跑接口。
- 不实现前端页面。

## Decisions

### 1. 测试任务按单个执行环境建模

本 change 的 API 使用一个 `environmentId` 创建一次远程测试运行。前端如果需要分别在 x86 和 RISC-V 上运行同一测试，应创建两次测试任务，或后续由编排层创建多任务。

理由：

- 当前需求只要求“测试输出和日志回收”，不是测试对比。
- 单环境任务与已有 `test_runs.environment_id` 字段一致，实现成本低。
- 双环境聚合和比较会引入新的结果关系、状态组合和展示语义，应交给后续 change。

### 2. 复用 SSH runtime 的脚本执行方式

测试命令可以作为命令执行；如果传入脚本文本，应按已有 CUSTOM_BASH 的安全策略上传为临时脚本后执行，避免 shell quoting 问题。执行完成后清理远端临时脚本。

理由：

- 用户脚本可能包含引号、换行、重定向和 heredoc。
- 直接拼接 shell 字符串风险高。
- 既有脚本执行能力已经处理过 stdin、远端脚本文件和清理语义。

### 3. stdout/stderr 同时进入实时日志事件和完整日志文件

worker 捕获测试输出后，应通过任务执行上下文写入 `task_log_events`，用于页面实时展示和恢复；同时继续写入完整日志文件并在 `task_logs` 中保存元数据。

理由：

- SSE 页面需要实时输出。
- 完整日志通常可能很大，数据库不适合保存完整正文。
- `task_logs` 已经是完整日志的权威引用。

### 4. 支持测试报告产物回收

创建测试任务时允许提交可选数组字段 `reportTargets`。数组中的每个条目包含 `type` 和 `path`：

- `type=FILE`：`path` 是相对 `workingDirectory` 的明确报告文件路径。
- `type=DIRECTORY`：`path` 是相对 `workingDirectory` 的报告输出目录，worker 在目录内按受控规则扫描并回收文件。

worker 在测试命令结束后，从远端工作目录解析这些目标并下载匹配文件，保存到对象存储或既有受控制品表。API 只返回报告文件名、大小、content type、sha256 和 artifact 引用。

理由：

- 有些测试程序会把正式报告写入文件，stdout 只输出很少内容。
- 报告文件可能比 stdout 更适合审计。
- 使用显式文件路径和受控目录扫描可以避免远端任意文件读取。

约束：

- `reportTargets` 未传或为空数组时表示不回收报告。
- `reportTargets[*].path` 必须相对 `workingDirectory` 或受控测试输出目录解析。
- 不允许绝对路径、`..` 越界、空路径或匹配隐藏敏感路径。
- `DIRECTORY` 类型必须限制扫描深度、文件数量、单文件大小、总大小和允许的文件扩展名或 content type。
- 单个任务回收文件数量、单文件大小和总大小需要配置上限。

### 5. 构建和测试执行支持前端传入环境变量

构建任务和自动化测试任务都允许请求体携带 `environmentVariables` 对象。后端在创建任务时将这些变量写入任务输入快照的受控区域，worker 远程执行命令或临时脚本时注入到执行环境。

约束：

- 变量名必须匹配后端允许的环境变量名格式，例如 `^[A-Z_][A-Z0-9_]*$`。
- 变量值必须有长度上限。
- 任务事件、审计日志和 API 摘要必须对变量值脱敏，尤其是名称包含 `TOKEN`、`PASSWORD`、`SECRET`、`KEY`、`PASS` 的变量。
- 环境变量只作用于本次构建或测试任务，不写入正式环境配置，不写入凭据表。

理由：

- 构建和测试脚本经常需要 `CC`、`CFLAGS`、`PATH`、`LD_LIBRARY_PATH`、测试开关等变量。
- 这些变量是前端按任务传入的运行参数，不应污染环境配置。

### 6. `test_runs` 保存运行摘要，不保存完整日志正文

`test_runs` 保存 `exit_code`、`status`、计数字段、日志引用和时间字段。计数字段在 MVP 中允许为空，因为本 change 不解析测试框架报告。

理由：

- 当前需求关注输出和日志回收。
- 摘要字段能支撑列表和详情。
- 结构化报告解析会扩大范围。

### 7. 取消和超时复用任务运行时

取消 `AUTOMATED_TEST` 时，先更新任务状态并投递取消消息，由 worker 尝试终止远程命令。超时时也走远程进程终止和受控终态写入。

理由：

- 与现有运行中任务取消模型一致。
- 不需要为测试任务建立第二套取消状态机。

## Risks / Trade-offs

- 远程命令输出过大可能导致实时事件量很高 → 限制单条日志事件大小，完整日志写文件，事件内容做分片和脱敏。
- 报告目录配置过宽可能回收大量文件或敏感文件 → 只允许相对目录，并限制扫描深度、数量、大小和解析根目录。
- 前端传入环境变量可能包含敏感信息 → 不作为正式凭据保存，摘要统一脱敏，并限制变量名和值长度。
- 远程命令退出后 SSH session 异常断开 → 已捕获的输出和退出状态尽量写入；无法确认退出码时标记失败并保存错误摘要。
- 用户测试命令包含敏感内容 → 命令、日志摘要和审计详情必须经过脱敏；完整日志下载仍需要权限校验。
- 只做单环境任务会让双环境测试需要创建多次任务 → 这是本 change 的边界，后续比较/编排 change 再聚合。

## Migration Plan

1. 如果现有 `test_runs` 字段已经满足摘要记录，优先复用；缺失输出摘要、报告 artifact 引用或必要元数据时通过 Liquibase 增量补充。
2. 添加 jOOQ 生成代码并保持普通 Maven build 不连接数据库 codegen。
3. 实现 API、service、repository、handler 和测试。
4. 使用真实或模拟 SSH 环境验证命令运行、日志回收和任务终态。

回滚策略：该能力以新增 API/handler 和兼容字段为主，回滚代码后历史 `test_runs` 记录仍可作为普通摘要数据保留。
