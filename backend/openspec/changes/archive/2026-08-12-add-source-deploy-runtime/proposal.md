## Why

构建验证需要在指定构建环境中运行，但当前源码版本只保存在后端本机目录中。需要新增一个可审计、可复用、可取消的源码部署运行时，把某个源码版本同步到指定环境的工作目录下，避免构建验证依赖用户手工准备远端源码。

## What Changes

- 新增源码部署任务，支持将 `sourceRevision` 的本机工作副本部署到一个或多个指定环境；构建验证前可同时部署到 x86 原始环境和 RISC-V 目标环境。
- 源码部署默认使用环境配置中的 `working_directory`，远端部署路径由后端生成，前端不传入任意远端路径。
- 新增源码部署记录，绑定项目、源码版本、环境、任务、远端路径、状态、统计摘要和时间信息。
- 新增源码部署 API，支持创建、查询详情、分页列表、取消部署。
- 源码部署接入现有任务、Worker、SSH、日志和 SSE 机制，部署进度和结果可被前端实时观察。
- 支持重复部署控制：相同源码版本和环境已有进行中或成功部署时默认复用，`force=true` 时重新部署并覆盖后端生成的远端目录。
- 部署失败时必须写入任务和部署记录的失败状态，不进入后续构建验证。

## Capabilities

### New Capabilities

- `source-deploy-runtime`: 定义源码版本部署到远端环境工作目录的 API、任务状态、路径生成、运行时行为和查询能力。

### Modified Capabilities

- `project-source-environment`: 明确环境 `working_directory` 是源码部署和后续构建验证的远端工作目录根路径。

## Impact

- 后端 API：新增源码部署创建、查询、列表和取消接口。
- 数据库：新增源码部署运行记录表，并通过 Liquibase 和 jOOQ 管理。
- 任务运行时：新增 `SOURCE_DEPLOY` 任务类型和 Worker handler。
- SSH 运行时：复用现有 SSH 命令执行、输入流、日志和取消能力。
- E2E：新增源码部署真实链路测试，覆盖正常流程、异常流程和边界条件。
