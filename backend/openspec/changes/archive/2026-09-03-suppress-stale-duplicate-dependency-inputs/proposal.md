## Why

当前数据库中存在历史依赖分析 run 生成的重复 `gcc` 输入引用，同一源码版本下可能同时保留旧的 `CONFIRMED` 与新的 `CANDIDATE` 依赖输入，导致评估报告或输入预览继续展示已经过期的重复项。现有重跑同步已能清空同来源输入，但缺少对历史脏数据和报告生成读取边界的明确约束。

## What Changes

- 依赖分析成功重跑后，继续以当前项目、源码版本和 `DEPENDENCY_RESULT` 为范围重建迁移输入，并确保历史重复依赖输入不会继续进入当前报告输入池。
- 报告生成和报告 readiness 只读取当前源码版本的有效迁移输入，并对同一依赖语义重复的历史引用进行抑制，避免同一 `gcc` 或同类工具/库重复进入报告。
- 依赖分析结果与迁移输入的关联应优先指向当前源码版本最新成功依赖分析 run 的结果；历史 run 仅用于显式历史查看，不作为当前报告默认输入。
- 提供一次性数据修复或受控清理逻辑，用于处理已有数据库中的重复 `DEPENDENCY_RESULT` 引用；历史报告快照保持不变。
- 补充单元测试和 E2E 覆盖：正常刷新、异常保留、edge case 历史重复抑制。

### New Capabilities

### Modified Capabilities
- `migration-input-refresh`: 明确历史重复 `DEPENDENCY_RESULT` 输入在当前输入池中的抑制和清理语义。
- `dependency-analysis-runtime`: 明确依赖分析结果同步迁移输入时只绑定本次最新 run，并避免多来源重复工具项重新进入当前输入池。
- `migration-report-runtime`: 明确报告 readiness、输入预览和报告生成不得消费过期或重复的依赖迁移输入。

## Impact

- 影响后端迁移输入同步、报告 readiness、输入预览和报告生成读取逻辑。
- 可能需要新增数据库清理逻辑或迁移脚本，清理已有重复 `DEPENDENCY_RESULT` 当前输入引用。
- 不修改历史报告快照，不破坏历史报告下载和详情查看。
- 需要补充针对迁移输入刷新、依赖分析同步和报告生成的测试。
