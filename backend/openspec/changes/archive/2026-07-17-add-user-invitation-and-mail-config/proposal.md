## Why

当前后端已经具备本地登录、强制改密和超级管理员用户管理能力，但用户创建仍依赖管理员直接设置初始密码，缺少邮箱邀请注册、忘记密码和邮件服务器配置能力。下一步需要让管理员创建用户后通过邮件发送一次性链接，由用户自主设置密码，同时为后续任务完成邮件推送提供统一的邮件配置基础。

## What Changes

- 管理员创建用户改为邀请注册流程：管理员创建用户后生成一次性邀请 token，并通过用户邮箱发送设置密码 URL。
- 新增用户接受邀请 API：用户通过邮件 URL 中的 token 设置密码并完成账号启用。
- 保留管理员直接重置密码 API：管理员仍可直接设置新密码，并可选择是否要求用户下次登录主动修改密码。
- 新增用户忘记密码流程：用户自行触发密码重置邮件，并通过一次性 token 设置新密码。
- 新增统一系统配置表，用于保存邮箱服务器配置以及后续 AI、知识库、通知等服务配置。
- 新增邮箱服务器配置 API、测试发送 API 和邮件发送服务。
- 新增任务完成邮件推送的基础开关和发送路径。
- 明确个人中心不允许用户修改自己的 `username` 和 `email`；邮箱只能由超级管理员修改。
- 补充对应单元测试和 API E2E 测试，覆盖正常流程、异常流程和 edge case。

## Capabilities

### New Capabilities

- `mail-configuration`: 统一系统配置表、邮箱服务器配置 API、邮件发送服务和任务完成邮件推送约束。

### Modified Capabilities

- `backend-api-design`: 调整用户创建为邀请注册，新增邀请接受、忘记密码、邮箱配置和任务邮件推送 API；保留管理员直接重置密码。
- `backend-database-design`: 新增统一配置表和用户 action token 表；保留 `users.username`、`users.email` 唯一性约束；明确不新增邮箱验证字段。
- `api-e2e-test-suite`: 补充用户邀请注册、忘记密码、邮箱配置、邮件发送和任务完成邮件推送的 E2E 覆盖要求。

## Impact

- API：认证 API、超级管理员用户管理 API、管理员配置 API、任务完成通知路径。
- 数据库：新增统一 `system_configs` 表和 `user_action_tokens` 表，复用现有 `users` 表唯一性约束。
- 安全：token 明文只出现在邮件 URL 中，数据库仅保存 token hash；响应、日志、审计不得泄漏 token、密码、SMTP 密码或邮件敏感配置。
- 基础设施：后端需要邮件发送依赖和可配置 SMTP 参数；本地开发需要可禁用真实邮件发送或使用测试发信模式。
- 测试：需要新增单元测试、集成测试和 E2E 测试，且按正常流程、异常流程、edge case 三类覆盖。
