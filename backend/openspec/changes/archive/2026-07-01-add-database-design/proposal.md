## Why

后端 MVP 在进入实现前需要先明确 PostgreSQL 数据模型。当前产品流程依赖可持久化的项目状态、可恢复的异步任务、可追溯的 KB/SBOM 结果、本地日志留存、加密凭据和可复现报告。

如果没有统一的数据库设计，环境管理、KB 扫描、SBOM 分析、问题汇总、构建验证、测试、报告生成和 SSE 任务更新等服务很容易形成互不兼容的状态模型。

## What Changes

- 定义 RvPort 后端 MVP 的 PostgreSQL 数据库设计。
- 确认 PostgreSQL 是任务状态、任务事件、业务结果和项目工作流状态的事实来源。
- 确认队列只用于投递 `task_id`，不作为权威任务存储。
- 定义平台自管的加密凭据存储，用于 SSH 和 Git 凭据。
- 定义本地日志元数据存储，完整日志保存在本地文件系统并按天打包。
- 定义 MVP 测试结果只保存退出码、通过数、失败数、跳过数，不解析 JUnit、CTest、pytest 等报告格式。
- MVP 数据库设计不引入通用 artifact 管理；报告、归档、日志路径按需保存在对应业务表中。
- 将项目阶段定义为缓存式导航提示，而不是权威线性生命周期，因为修复后的代码可能在报告、构建或测试之后重新入库。
- MVP 不持久化用户角色、用户角色映射和项目成员；只保留本地用户，用于登录、创建人引用和审计操作人引用。
- 新增 `users.is_super_admin`，并要求环境初始化脚本第一次运行时创建默认超级管理员：`username = 'admin'`，初始密码输入为 `admin123`。

## Capabilities

### New Capabilities

- `backend-database-design`：定义项目、用户、源码版本、环境、凭据、异步任务、任务事件、日志、工具运行、KB 扫描结果、SBOM 分析、问题汇总、报告、复检、构建验证、测试、归档和审计的数据库要求。

### Modified Capabilities

- 无。

## Impact

- 影响后端 Schema 设计、持久化边界、任务编排、SSE 事件恢复、凭据处理、日志留存和所有 MVP 后端服务。
- 使用 PostgreSQL 的 `jsonb`、`timestamptz`、`uuid` 等能力和必要索引。
- 后端服务和 worker 即使使用队列做异步投递，也必须将任务状态和任务事件持久化到 PostgreSQL。
